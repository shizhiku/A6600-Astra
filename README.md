# 01 · 方案总览

## 1. 目标

把 **Sony ZV-1M2（五代 ASTRA）的新触控 UI** 移植到 **ILCE-6600（a6600，四代）**，
方式是：保留 a6600 的四代硬件底盘（`im.elf` / `libObj.so` / `libInfraSKD.so` / `/sabin`），
换掉 `/usr` 里的 UI 层，用引导垫片把五代 `appFw.so` 拉起来。

参照实现：`nolan2628/ZVE10-Astra-Public`（同一套方案，成功跑在 ZV-E10 真机上）。

---

## 2. 可行性判断（分三段）

### 2.1 平台层：成立 ✅

| 项 | a6600 | ZV-E10 | 判断 |
|---|---|---|---|
| SoC | CXD90045（`Hardware: ARM-CXD900X0`） | CXD90045 | **同平台** |
| CPU | Cortex-A5 ×4，无 NEON（`0x0c05`） | 同 | 同 |
| 宿主 | `im.elf` + `libIMDB.so` 模块表 | 同 | 同构 |
| UI 层 | `libObj.so` + `viewUnified2..8.so` | 同 | 同构 |
| 内核 | `3.0.27_nl-rt106+` | 同族 | 同 |
| glibc | 2.11.2 | 2.11.2 | 同 |

**结论：a6600 是"同平台、不同机身"，移植属于"重新标定"，不是"从零研究"。**

### 2.2 固件层：成立 ✅（已实测）

- a6600 1.10 固件可完整解包（`nflasha3/5/7/15` + `0800_appli` + `.sum`）
- 重打包可做到**与索尼原包逐字节一致**（S0，见 02）
- 相机端更新链**只验 CRC32，无 RSA**（CXD90045 平台特性，anlock6600 全链路反汇编 + CST 跨平台研究双重确认）
- 因此：**改内容 → 重算 CRC → 重新封装，原理上是通的**

### 2.3 UI 层：**阻塞** ⛔

ASTRA 的 UI 本体是 5 个库 + 232 个资源，**只存在于 ZV-1M2 的固件里**：

```
lib/appFw.so            64,273,528 B
lib/libObj_g5.so         3,931,624 B
lib/libmpr_g5.so         3,038,540 B
lib/AdjChkConfig.so         82,440 B
lib/libappFwBoot_g5.so       8,312 B
share/app/                   232 个文件
```

而 ZV-1M2 的官方包用**未公开的容器密钥**加密（已用 4 个公开密钥逐个实测，全部失败）。
详见 [`03-缺口与原料清单.md`](03-缺口与原料清单.md)。

## 3. 路线图（S0 → S5）

| 阶段 | 内容 | 输入 | 产出 | 状态 |
|---|---|---|---|---|
| **S0** | 固件解包 / 重打包链路 | a6600 官方包 + `key_cxd90045` | 逐字节一致的重打包器 | ✅ **完成** |
| **S1** | 取得五代库 | ZV-1M2 dump 或密钥 | 5 库 + 232 资源 | ⛔ **阻塞** |
| **S2** | a6600 宿主分析 | a6600 `/usr` + S1 的库 | 补丁点、模块表、符号冲突表 | 🟡 无库可做一半 |
| **S3** | 引导垫片移植 | S1 + S2 | `appFwBoot_g4host.c` 的 a6600 版 | ⬜ |
| **S4** | 硬件桥接 | S3 | 触控 / EVF / IBIS / `av-cam` 适配 | ⬜ |
| **S5** | 真机验证 | 全部 | 可刷镜像 + 回滚方案 | ⬜ |

### S0 · 固件链路（已完成）

1. 解包：`DAT → FDAT → tar → nflasha3/5/7/15`
2. 重加密：AES-ECB 首块 + AES-CBC 链，1024 B 块校验和 + end flag
3. 重建 DAT：同 chunk 顺序 + DEND CRC32 重算
4. **验收：与原包逐字节一致（316,672,424 B，SHA-256 相同）**

### S1 · 原料（阻塞点）

三条路径，按可行性排序：

1. **拿到一台 ZV-1M2** → 尝试从其服务通道 dump `/usr`（难点：CXD90057 平台通道未打通）
2. **向作者要密钥**（32 字节格式事实，非二进制）
3. 等社区公开

### S2 · 宿主分析（拿到库后，1–2 周）

| 项 | ZV-E10 参照值 | a6600 需要 |
|---|---|---|
| `im.elf` 补丁点 | 文件偏移 `0x175e`（`02 46` → `01 22`） | 重新定位（a6600 `im.elf` 尺寸不同） |
| `libMWF.so` 补丁点 | VA `0x2d2ac`（`a0 b1` → `00 bf`） | 重新定位（a6600 库尺寸不同） |
| `libIMDB.so` 模块表 | 37,044 B 版；`appfw_off=0x7CA4`、`str_off=0x5530` | **整表重做**（a6600 为 33,924 B，布局不同） |
| 符号冲突扫描 | 557 个（Ob5 352 / mp5 190 / appFw 108 / AdjChk 72 / boot 25） | 重新扫（a6600 `libObj.so` 20.9 MB vs 21.3 MB） |
| `libObjShim` 空桩 | 103 个函数 + 2 个 `sidb` 符号 | 按 a6600 实际未解析 PLT 重算 |

### S3 · 引导垫片（拿到库后，2–4 周）

复用 ZVE10 的 `appFwBoot_g4host.c`（6,257 行）作为骨架，替换：

- 16 MB 专用栈线程（保留）
- `__assert_fail` / `abort` 免疫（保留）
- `condition_variable::wait` 2 秒超时兜底（保留，a6600 服务更少，更需要）
- 五代库加载顺序（按 a6600 实际依赖闭包重排）
- 真机 RM 交接点（`libMWF` 影子继承偏移需重定位）

### S4 · 硬件桥接（最难的一段）

| 项 | ZV-E10 | a6600 | 影响 |
|---|---|---|---|
| 屏幕 | 3" 640×480 | 3" 640×480 | ✅ 可直接复用 |
| 触控事件 | `0x026c` | 待确认（大概率同） | 🟡 需实测 |
| **EVF** | 无 | **有**（0.39" XGA OLED） | 🔴 ASTRA 无对应 UI 与数据结构 |
| **IBIS** | 无 | **有**（5 轴） | 🔴 ASTRA 无对应菜单与状态机 |
| `av-cam` 命令表 | 337 条 | **286 条** | 🔴 缺 51 条，需逐条兜底 |
| 按键布局 | 无 EVF/前拨轮 | 有 EVF 感应/前拨轮/AF-ON | 🟡 按键派发表需重映射 |

### S5 · 真机验证（最后一步）

前置条件（缺一不可）：

1. 全分区 dump（`nflasha1/2/3/5/7/15/B0`）并留哈希
2. **验证过可用**的恢复流程
3. 第二台相机，或已定位的 UART 救砖点
4. 先做 **byte-identical 重打包**的上机实验（内容不变，只验证封装被接受）

## 4. 与 ZVE10-Astra 的关系

| 项 | ZVE10-Astra | 本项目 |
|---|---|---|
| 目标机型 | ZV-E10（Gen4 CXD90045） | a6600（Gen4 CXD90045） |
| 源机型 | ZV-1M2（Gen5 ASTRA） | 同 |
| 方法 | 换 `/usr` + 模块表重定向 + 符号隔离 + 16MB 栈垫片 | **完全一致** |
| 差异 | — | 全部偏移、模块表、冲突表、硬件桥接需重标定 |

**换句话说：他们踩过的坑我们大部分不用再踩，但每个数字都要重新量。**
