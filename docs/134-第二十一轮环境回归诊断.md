# 134 · 第二十一轮：环境回归诊断 + 崩溃地址定位

> 时间：2026-11-22。离线 QEMU。

## 一、先纠正我自己上一轮的判断（依据参考项目的说明）

| 我之前的说法 | 纠正后 |
|---|---|
| `GRM_fbrmCheckUpdateFinished` 要求返回 1 | **错**。`0` 才是成功，`0xFFFFD8F1` 是"未完成"。`==1` 的判断只发生在它内部对 helper `0x11F766` 的检查 |
| `fbrm` 单例未初始化 | **错**。`0x11F6E0` 有完整懒初始化路径（`__cxa_guard_acquire` + 构造 `0x11F6AC`），构造函数会把 `+0x58/+0x5C/+0x60` 清零 |
| bit0 是"显示就绪"标志 | **错**。是 C++ 局部静态对象的 guard 变量 |
| `g_gemini_fb` 是原厂隐藏缓冲 | **错**。是参考项目自己的 `static uint32_t g_gemini_fb[800*600]`，我环境里不存在 |
| 只 patch 完成检查就能出图 | **错**。参考项目还接管了 DMP/Gemini 软件绘制、纹理、Swap、Present、engine wait |
| 参考项目 patch libObj | **错**。它 patch 的是 **appFw 的导入 GOT 槽**，且**先调原函数再强制返回 0** |

据此我把补丁改成参考语义：**保留 `bl 0x11F766` 调用，再 `movs r0,#0; pop {r7,pc}`**。

- 补丁位置：`libObj` 文件偏移 `0x115618 + 8`，4 字节 `02 4b 01 28` → `00 20 80 bd`
- 结果字节：`80 b5 00 af 0a f0 a3 f8 00 20 80 bd`
- 产物：`03-证据/静态分析/97_abi/a5bObj_fbrm2.img.so`（SHA256 `0b587fab...`）
- 镜像：`/root/astra/97/m1-verified/astra-m1-fbrm2.img`（SHA256 `a501005f...`，补丁已验证写入）

## 二、但运行全部失败——且**对照实验证明与补丁无关**

| 实验 | 结果 |
|---|---|
| `astra-m1-fbrm2.img`（带补丁）× 4 次 | **4/4 失败** |
| `astra-m1-astra7.img`（**不带补丁**）× 2 次 | **2/2 失败** |

**未打补丁的旧镜像同样失败** → 不是补丁引入的问题，是**环境层面发生了回归**。

且失败点一致：串口只输出 `[ASTRA97] bridge7 enter` 一行，之后进入 exception monitor。

## 三、崩溃现场（重要）

```
[current task]
program: im.elf(THREAD_APP) (pid: 359, cpu:0)
address: 08249000, trap_no: 0000000e, error_code: 00000817
[Exception Syndrome]
page translation fault (0x817) at 0x08249000
```

**崩溃地址 `0x08249000` 落在：**

```
08249000-0824a000 ---p 00000000 00:00 0
```

即一块 **`---p`（不可读/不可写/不可执行）匿名映射**。

## 四、已排除的假设

| 假设 | 检查结果 |
|---|---|

| 我改的 QEMU GPU 追踪代码导致 | 追踪代码仅在 `REA_GPE_TRACE` 环境变量存在时执行；对照跑未设该变量仍失败。**但不能完全排除**（`04:44` 重建过 `qemu-system-arm`）|
| `0x08249000` 是硬编码地址 | ❌ 在 `a5pFw`(64MB) 和 `libObj`(3.9MB) 里**各 0 处命中**，说明是运行期算出来的 |

## 五、当前状态：这是一个**未收敛的回归**

我在这条线上已经消耗多轮仍未定位，且每一轮结论都在被新证据推翻。**诚实记录如下**：

1. 补丁本身是正确且按参考语义做的（已静态验证）；
2. 但**基础镜像现在跑不起来了**，所以无法验证补丁效果；
3. 崩溃是 `THREAD_APP` 解引用了一个指向 `---p` 区域的地址 `0x08249000`（野指针），该值不来自库内硬编码；
4. 之前能跑通的运行，与现在的差别**只知道 QEMU 在 `04:44` 被重建过**（为加 GPU 追踪），但没有原始二进制可回退对比。

## 六、要恢复可复现性，需要做的一件事

**重建一个"干净"的 QEMU**（不带 `REA_GPE_TRACE` 改动），然后重跑对照实验：

- 若干净 QEMU 能让 `astra7` 恢复成功 → 确认是追踪改动引入
- 若仍失败 → 说明是镜像/环境其他因素，需要进一步二分

这是唯一能一次性判定方向的动作，也是我建议的下一步。
