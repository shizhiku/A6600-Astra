## 二、这证实了上一轮的推断

- 字体**不在** `/usr`（与我们扫描更新包 /usr 的结论一致）；
- 字体**确实在运行时出现在 `/tmp/images/`**；
- 由 `libsencore.so`（副控制器通信库）在运行时获取并落盘。

**因此：模拟器里 UI 崩溃的直接原因就是 `/tmp/images` 里没有这个字体。**

## 三、下一步：把字体喂给模拟器（不改固件）

模拟器的根文件系统是 initrd 里的 ext2（仅 2.18 MB），放不下 1.96 MB 的字体，且 `/tmp` 可能被 tmpfs 覆盖。推荐做法：

1. 把字体放到 **`/usr` 分区**（`nflasha15`，215 MB，空间充足）的 `/share/app/` 下；
2. 修改该分区中的 `/share/app/fontlist.dat`，把 `FONT_S_CHINESE` 的路径从
   `/tmp/images/MYingHeiC-GB18030-SJ_wIcon.ltt`
   改为
   `/usr/share/app/MYingHeiC-GB18030-SJ_wIcon.ltt`；
3. 用修改后的 `/usr` 镜像启动，观察 UI 是否越过 abort。

说明：这属于**模拟器输入适配**（把外部资源改为本地可读路径），不涉及修改固件逻辑，也不用于刷机。

## 四、待办
