# 126 · 如何补齐剩余证据（可执行清单）

> 时间：2026-11-22。本文回答"缺失的证据怎么补齐"，分两条线给出**具体步骤、所需工具、产出物、预计难度**。

## A. 移植侧：唯一缺口 = `0x54EF8C` 的虚函数身份

### A-1 静态路线（首选，零风险，纯离线）

**目标**：确定 `0x54EF74` 中 `blx r3` 调用的到底是哪个虚函数。

**已确认的事实链**：

```asm
; ---- Application_Start (0x54D580) ----
0054d594  add.w r0, r7, #0x880
0054d598  adds  r0, #0x1c          ; r0 = r7 + 0x89c
0054d59a  bl    0x54D154           ; 构造对象 A（在 r7+0x89c）
0054d59e  add.w r1, r7, #0x880
0054d5a2  adds  r1, #0x1c          ; r1 = r7 + 0x89c
0054d5a4  mov   r0, r7             ; r0 = r7（外层结构）
0054d5a6  bl    0x54D2B0           ; 0x54D2B0(外层, 对象A)
0054d5aa  mov   r0, r7
0054d5ac  bl    0x54F664           ; ← 进入后阻塞

; ---- 0x54D2B0 ----
str r5, [r4, #0x10]                ; 外层->[+0x10] = 对象A 指针

; ---- 0x54F664 → 0x54EF74 ----
0054ef80  ldr r0, [r0, #0x10]      ; r0 = 对象A
0054ef86  ldr r3, [r0]             ; r3 = 对象A->vtable
0054ef8a  ldr r3, [r3]             ; r3 = vtable[0]
0054ef8c  blx r3                   ; ← 待确定的虚函数

; ---- 0x54D154（写入 vtable）----
0054d158  ldr r4, [pc, #0x14]      ; 字面量 @0x54D170 = 0x0322DA62
0054d160  ldr r3, [pc, #0x10]      ; 字面量 @0x54D174 = 0x0005E9F0
0054d162  add r4, pc               ; r4 = 0x54D164 + 0x0322DA62 = 0x0377ABC6
0054d166  ldr r3, [r4, r3]         ; r3 = *(u32*)(0x0377ABC6 + 0x5E9F0) = *(0x037D95B6)
0054d168  adds r3, #8
0054d16a  str r3, [r5]             ; 对象A->vtable = 该全局 + 8
```

**卡点**：`0x0377ABC6` 比 `.got`（`0x0377ABC8`）小 2 字节，导致取到的值不是合法指针。

**下一步要做的三件事**：

| 步骤 | 做法 | 预期产出 |
|---|---|---|
| A-1.1 | 重新确认 `add r4, pc` 的 PC 语义。Thumb 下 `add rX, pc` 用 `(insn_addr + 4) & ~3`；但若该指令实际是 32-bit Thumb-2 编码，PC 取 `insn_addr + 4`（不再对齐）。用 capstone 以 `CS_MODE_THUMB` 逐条验证 `0x54D158..0x54D16A` 的**编码长度**（16/32 bit） | 正确的 `r4_base` |
| A-1.2 | 若 `r4_base` 仍偏移 2 字节，说明 `0x54D162` 是 32-bit 指令（`add r4, pc` 的 Thumb-2 形式），PC = `0x54D162 + 4 = 0x54D166`，则 `r4_base = 0x54D166 + 0x0322DA62 = 0x0377ABC8`（正好 `.got` 起点） | 精确的 GOT 槽 |
| A-1.3 | 得到 vtable 地址后，dump `vtable[0]`，映射到 `.text` 内的函数，并用**字符串交叉引用**判断类名（`0x54D154` 附近应有所属类的名字或日志串） | **虚函数地址 + 类名** |

**产出**：`03-证据/静态分析/vtable/` 下的解析报告 + `01-文档/127-0x54EF8C虚函数定位.md`。

### A-2 运行期路线（备选，需 QEMU）

如果静态路线失败，用**最小侵入**的运行期探针：

- 不 trap 指令，而是 **LD_PRELOAD 拦截 `0x54D154` 会调用的东西**（`0x54D138`），或在 `0x54EF8C` 前用一个只写一次内存的短桩（保留原指令后跳回），把 `r3` 写到一块已知地址；
- 关键约束（已验证）：**布点不能超过 2-3 个**，`deep2` 的 16 点会导致启动崩溃。

### A-3 拿到虚函数后怎么定位阻塞

| 虚函数类型 | 应对 |
|---|---|
| `pthread_cond_wait` / `osal_rcv_msg_tmo` | 按 `105-grm_init阻塞分析` 的方法查它的前置初始化与消息生产者，补生产者 |
| `ioctl`（GPU/显示） | 检查 QEMU 侧 `dmp_smaph.c` 是否对该 ioctl 返回了期望值 |
| 文件/设备 open | 检查镜像里对应路径是否存在（已发现缺 `/share/screenreader`） |
| 纯计算 | 说明阻塞不在这里，继续向 `0x925FB0` 之后追 |

## B. 可刷入性侧（F2 是核心空洞）

### B-1 优先级最高的四件事（P0）

| # | 缺什么 | 怎么补 | 难度 |
|---|---|---|---|
| B-1.1 | **FDAT 尾部 256 B 的身份/生成/校验范围** | ① 取得**原始官方 DAT/EXE 存档**（Downloads 里 `BODYDATA.DAT` 就是 ZV-1M2 原件，可作比对）；② 对 `updaterbody.so` 里 trailer 相关函数做完整反汇编；③ 对比官方包与我们重封装包的同位置字节 | 中（需完整反汇编） |
| B-1.2 | **updater 接受/拒绝判定点**（`CheckGuardResult`/`ModelFile`/`VersionFile`/`RegionFile`） | 完整反汇编 `libupdaterbody.so` 的这几个函数（当前只有符号和 vtable），确定**拒绝发生在写入前还是写入后** | 中-高 |
| B-1.3 | **外部结论冲突**（PMCA README 说签名 vs anlock6600 说只 CRC32） | 复现 anlock6600 的分析链 `im.elf → libIMDB → libupdaterufp → crypter`；核实 PMCA 说的"签名"约束对象（自定义 body 还是整包） | 中 |
| B-1.4 | **`uc_crc32sum -s -c` 的 size 语义** | 该 10 KB ARM ELF 目前反汇编为空（`.disasm.txt` 是空文件）——需要用能处理 ARM ELF 的工具重新反汇编（objdump/ghidra），或构造离线单测模拟 `-s` 行为 | 低-中 |

### B-2 已可去掉的缺口（本轮补上，不需再做）

| 项 | 已补上 |
|---|---|
| F3 的 300 MiB 疑点 | 真机 `/proc/partitions`：`nflasha15`=307200 KiB=300 MiB，与 M1 一致；215,517,184 是 ext2 使用量 → **缺口消除** |
| `/tmp`/`/etc` 共享 inode | 真机 `/proc/mounts` 证实共用 `nflasha10` |
| a6600 真机库指纹 | `libObj.so`=20,889,004 B；`appFw.so` 不存在 |

## C. 建议的执行顺序

```
第1步  A-1.1/A-1.2：修正 Thumb PC 语义，拿到 vtable        [纯离线，1 小时]
第2步  A-1.3：dump vtable[0]，查类名                        [纯离线，1 小时]
第3步  A-3：按虚函数类型决定"补初始化"还是"绕过"             [离线+QEMU，数小时]
第4步  出画面 → M-E 达成 → 目标第 4 项闭合
第5步  B-1.4（最易）→ B-1.1 → B-1.2 → B-1.3 逐步闭合 F2
```

**关键判断**：第 1-2 步完全不需要 QEMU，也不需要真机，是当前性价比最高的动作。

## D. 边界

- A 路线纯离线，零风险；
- B 路线中"取得原始官方 DAT"属于只读资料收集，不涉及真机写入；
- 任何真机写入仍需用户逐次明确授权。
