## 一、相机当前不可用

`usbipd list` 与 WSL `lsusb` 中均无 `054c:*` 设备（连大容量存储模式也没有枚举）。因此本计划中的「只读采集真机 `/lib/libc-2.11.2.so`」未能执行。

**需要用户重新连接/开机相机后继续。**

## 二、上一轮结论（问题 B 根因）

已定位：应用在 libc 偏移 `0x9AC2A` 处调用 **syscall 191（rlimit 一族）**，`svc` 返回后出现 SIGILL。

内核镜像中确认存在：

```
"Oops - bad syscall."
"%s (%d): undefined instruction: pc=%p"
```

即该内核对被禁用/未知的系统调用号会按**未定义指令**处理并投递 SIGILL。

## 三、本轮未能完成的静态定位

尝试通过字符串地址的字面量引用找到 `bad syscall` 判定代码，在 `0x60000000`、`0x60008000`、`0x60010000`、`0x60004000`、`0x60018000` 五个候选基址下**均未找到字面量引用**。

原因判断：内核代码为 Thumb-2，地址通过 `movw`/`movt` 成对编码，不会以 4 字节字面量出现。若要定位，需要扫描 `movw/movt` 指令对，成本较高。

### 已准备好的「一条命令验证」

`02-脚本/verify_live_libc.py` 已完成并通过语法检查。相机上线后执行：


它会：

- 直接打印结论（“一致 / 不同构建 / 大小不同但现场一致”）。

### 内核交叉引用定位：本轮失败

尝试用 `movw/movt` 指令对定位引用 `"Oops - bad syscall."` 的代码：

- Thumb-2 版本扫描：全镜像仅得 1 对，无匹配；
- ARM 版本扫描：仅得 2 对，无匹配。

这说明该内核镜像的代码布局与两种假设都不符（可能为压缩镜像，或字符串与代码不在同一线性映射）。**此路暂缓**，等 libc 比对结论后再决定是否需要。
