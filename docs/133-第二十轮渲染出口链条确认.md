> 时间：2026-11-22。依据：参考项目 ZVE10-Astra-Public 源码链路说明 + 我方对五代 `libObj.so` 的静态验证。

## 一、参考项目提供的决定性信息

`g5_hook_present` 的实际链路：

```
五代 appFw / WidgetSystem 产生绘制调用
  ↓
Gemini / DMP 软件绘制钩子
  ↓
软件画布 g_gemini_fb
  ↓
g5_hook_swap_buffers   把画布打包成 8×8 Morton RGBA4444
                       写入默认源缓冲 0x20589300（或缓冲描述中选出的其他地址）
                       然后调用原 swap
  ↓
g5_hook_present        读取 Present 参数里的 src_phys / dst_phys
                       把 Morton 解包成线性 RGBA4444
  ↓
export_frame_data      主 Present 时把线性像素复制到 0x20000000
                       输出 ASTRA_FB_SYNC
  ↓
宿主 QMP pmemsave      读内存 → RGBA8888 → PNG → Web
```

**关键澄清（参考项目自己纠正的）**：

- `0x20589300` 是 **Morton 排列**，`0x20000000` 是**线性排列**；
- 宿主解码器只按像素展开 RGBA4444，**不再做 Morton 解包**；
- **能在 Web 显示 ≠ 已经通过 ch53/GPE 原生链路显示**；
- `g5_hook_engine_wait` 对 `engine==2` 直接 `return 0x40000000`（软件放行，不是硬件完成证明）；
- QEMU 构建把 `GRM_fbrmCheckUpdateFinished()` 的非零结果改成零，让 `drawFramebuffer` 继续；真机构建透传原结果。

**最重要的一条**：参考项目的 QEMU 截图**不能**作为"原生显示提交已验证"的证据。必须把两个目标拆开：

| 目标 | 内容 | 参考项目状态 |
|---|---|---|
| **T1 软件出图** | 五代 UI 画到软件画布 → 导出像素 → 抓到 PNG | ✅ 已实现 |
| **T2 原生显示** | 五代 `rm_present` 经四代原生 GPU/GPE/VDF 链路输出到后屏 | ❌ 未验证 |

## 三、`draw=0` 的直接原因已定位

### 3.1 `GRM_fbrmCheckUpdateFinished`（`0x115618`）

```asm
00115618  push {r7, lr}
0011561a  add  r7, sp, #0
0011561c  bl   0x11F766          ; 真正的完成状态查询
00115620  ldr  r3, [pc, #8]      ; 取一个非零常量
00115622  cmp  r0, #1
00115624  ite  ne
00115626  movne r0, r3           ; != 1 → 返回非零 = "未完成"
00115628  moveq r0, #0           ; == 1 → 返回 0  = "已完成"
0011562a  pop  {r7, pc}
```

### 3.2 `0x11F766`（真正的状态查询）

```asm
0011f766  push {r7, lr}
0011f768  sub  sp, #8
0011f76c  bl   0x11F6E0          ; 取状态对象
0011f770  adds r1, r7, #4
0011f772  bl   0x12548C          ; 读出状态到 [r7+4]
0011f776  ldr  r0, [r7, #4]      ; r0 = status
0011f778  rsbs.w r0, r0, #1      ; r0 = 1 - status
0011f77c  it   lo
0011f77e  movlo r0, #0           ; status > 1 → 0
0011f786  pop  {r7, pc}
```

**返回值 = `1 - status`（status>1 时归零）。**

外层要求**返回值恰好为 1** 才算完成，即要求 **`status == 0`**。

在我们的 QEMU 环境里 `0x12548C` 读出的 status 不是 0 → `1-status ≠ 1` → 判定"未完成" → **`drawFramebuffer` 被跳过 → `draw=0`**。

**这与我方"ch53 从未被编程"的观察完全一致，也解释了为什么逻辑跑通但画面不动。**

## 四、策略调整：把 T1 和 T2 彻底分开

### 4.1 立即目标改为 T1（软件出图）

参考项目已经证明 T1 可行。我们要做的对应工作：

| 步骤 | 内容 |
|---|---|

### 4.2 T2（原生显示）延后，且需单独取证

T2 需要确认目标机显示控制器接受什么提交：

- 扫描的帧缓冲物理地址、像素格式、行跨度、缓冲数量与切换方式；
- 缓冲所在物理内存由谁分配，CPU/DMA 间缓存一致性要求；
- 通过什么硬件状态/中断/远端回执确认帧已被消费。

**参考项目未做这一步，我们不能用它背书。**
