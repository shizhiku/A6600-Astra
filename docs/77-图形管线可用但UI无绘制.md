# 77 · 图形管线是通的：清屏+整屏拷贝都执行了，但 UI 没有提交绘制

本轮为 QEMU 模型调试与运行分析。无设备写入。

## 一、GPU 模型确实在执行命令

新增命令表/填充日志后，观察到：

```
[PSC] a=0x202e0200 size=614400 val=0x00000000 bpp=2
[DMP] psc-fill addr=0x202e0200 n=614400
[DMP] ppf-transfer addr=0x23a80000 n=614400      ← 拷进帧缓冲
[DMP] ppf-transfer addr=0x23b16000 n=614400      ← 第二个缓冲
```

- `psc-fill`：把 0x202E0200 处 614400 字节（640×480×2）填成 **0x00000000**
- `ppf-transfer`：把该缓冲整屏拷到帧缓冲 0x23A80000 / 0x23B16000

**即：清屏与整屏拷贝这条链路在模拟器里是工作的。**

## 二、黑屏的真正原因：UI 只清屏、不绘制

命令表内容（19 次提交，内容完全一致）：

```
reg 0x116 = 0x02053bb0
reg 0x117 = 0x00000001
reg 0x044 = 0x00000000
reg 0x010 = 0x12345678   ← 魔数
```

- 每次只有 4 条寄存器写入，**没有 draw kick（reg 0x202）**
- `0x12345678` 是典型的"写回读自检"魔数
- 19 次重复 → 更像周期性探测/心跳，而不是绘制

结论：**UI 侧启用了显示与清屏，但没有提交任何实际绘制命令。**

## 三、这意味着什么

- 图层通路（ch53 双缓冲、PPF 整屏传输、PSC 填充）已验证可用；
- 但 UI 没有内容可画，最可能的原因仍是**上游依赖缺失**——相机/传感器数据（YUV 层一直 off：`YUV layer still off`）或副控制器（sen）状态。
- 即：图形不再是瓶颈，**瓶颈回到"相机子系统/副控制器"这一层**。
