# 25 · 判据对象的真实来源：SIO ch0 帧计数

本轮为离线 QEMU 观测与离线数学分析。无设备写入。

## 一、对象 `0x640E46A0` 由 SIO 帧写入

对真机镜像下的对象地址设写监视，捕获到写入点固定为 `0x63A82884`，写入值依次为：

```
390E0000
390F5400
390F543E
390F547C
390F54BA
390F54F8
390F5536
390F5574
...
```

与同一次启动的 SIO ch0 发送日志格式完全一致（`39 0F 54 xx …`），第 3 字节按 **0x3E** 步进。

即：`[obj+3]` 是 **SIO ch0 帧计数器的一个字节**。

## 二、等待目标 `0x40` 的相位分析

判据为：

```
r5 = ([obj+3] ^ (global << 4)) & 0x7F
r5 == 0  → 成功（清零并继续）
```

当前 `global = 0x04`，故要求：

```
([obj+3] ^ 0x40) & 0x7F == 0
⇒ [obj+3] & 0x7F == 0x40
⇒ [obj+3] ∈ {0x40, 0xC0}
```

而 `[obj+3]` 从 `0x00` 出发、每步加 `0x3E`（mod 256）：

```
k=0 → 0x00, k=1 → 0x3E, k=2 → 0x7C, k=3 → 0xBA, k=4 → 0xF8, k=5 → 0x36, ...
```

解同余式 `0x3E·k ≡ 0x40 (mod 256)`，即 `62k ≡ 64 (mod 256)`，化简为 `31k ≡ 32 (mod 128)`，得

```
k ≡ 96 (mod 128)
```

**即：只有当该计数器恰好走到第 96 步（模 128）时，判据才成立。**

## 三、这意味着什么

- 等待目标不是“某个设备就绪”，而是 **SIO 帧计数器的特定相位**；
- 重试上限 30 次；若重试与帧计数推进的相位关系固定，30 次内可能永远打不到 k≡96；
- 真机存在时序抖动，相位会漂移，最终能命中；确定性模拟（`-icount shift=0`）下相位可能被锁死。

## 四、本轮的两个失败实验（必须记录）

### 4.1 去掉 icount

用 `QEMU_EXTRA=""`（无 `-icount`）运行 120 秒：

- 日志中 `LIRO` 出现 **0 次** → av-cam 根本没有加载；
- 内核停在 eMMC 时序警告上直到超时。

因此“无 icount 时故障消失”的说法**不成立**：程序根本没跑到那一步。**已撤回该推断。**

### 4.2 icount shift=1

尝试 `-icount shift=1,sleep=on`，脚本未产生新的运行目录（启动阶段即失败），原因待查。本轮无结论。

## 五、下一步

1. 排查 `-icount shift=1` 启动失败的原因（可能是 QEMU 参数或脚本问题）。
