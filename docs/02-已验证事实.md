## 7. 启动机制：warm boot，不走 execve

| 证据 | 值 |
|---|---|
| 内核 cmdline | `warm.mode=2`、`cmpr.path=/system/sabin/ssboot.bin` |
| `im.elf` PID | **149**，`Uid: 0` |
| `im.elf` 的 `/proc/149/environ` | **无 `LD_PRELOAD`** |
| 全进程 `/proc/*/maps` 扫描 | **无** `astra_probe` |

⚠️ **推论**：a6600 开机时 `im.elf` 由 `/system/sabin/ssboot.bin` 的休眠快照恢复，**不经 `execve`**。
因此 `bootin.elf` 里"读 `dmode`/`preload` → 拼 `LD_PRELOAD` → 启动 `im.elf`"那段**在正常开机时不执行**。

## 8. `/etc/ld.so.preload` 实验（失败，但结论明确）

步骤：写入 `/etc/astra_probe.so`（5,232 B，读回逐字节一致）+ `/etc/ld.so.preload` = `/etc/astra_probe.so` → 冷启动。

结果：

- 相机**正常启动**（说明坏 preload 不会阻断启动）
- `/setting/mode/astra_probe.log` 与 `/tmp/astra_probe.log` **均不存在**
- 即：**冷启动后没有任何进程被 exec 并加载它**

⚠️ **推论**：a6600 的启动过程几乎不产生"动态链接进程的 exec"，缺少 A6400 那种 `bsa_server` 触发点（或蓝牙未开）。

## 9. 重打包验证（S0 核心）

```
重加密密文   316,672,000 B  与原包逐字节一致 ✅
DEND CRC     原 157D2ED5 / 新 157D2ED5        ✅
重建 DAT     316,672,424 B  与原包逐字节一致 ✅   耗时 6.3 s
```

**结论：a6600 固件的加密封装逻辑与索尼完全等价，可任意改内容后重新封装。**

相机端校验链（anlock6600 反汇编结论）：`im.elf → libIMDB → libupdaterufp → crypter`，
**只有 CRC32，无 RSA**；256 B trailer 无任何可提取代码读取（是否被 ROM 校验未知）。

## 10. ZV-1M2 官方包解密尝试（失败）

| 项 | 值 |
|---|---|
| 文件 | `BODYDATA.DAT` |
| 大小 | `627,176,840` B（与索尼 ZV-1M2 2.01 页面完全一致） |
| 结构 | `DATV/PROV/UDID(60)/FDAT(627,176,720)`，**无 DEND** |
| IV | `f6462bfc088e2f3dd1c93335d261a26f` |

四个公开密钥逐个测试（首 32 帧校验和）：

| 密钥 | 结果 |
|---|---|
| `key_cxd90045`（a6600/ZV-E10） | 32/32 失败 |
| `key_cxd90057_k8`（a6700/a7R5） | 32/32 失败 |
| `key_cxd90057_k0` | 32/32 失败 |
| `key_cxd90014`（a6000 系） | 32/32 失败 |

**对照实验**（证明工具链正确）：同一套代码解 a6600 官方包，`key_cxd90045` → **bad 0/32** ✅。

**结论：ZV-1M2 用的是未公开的容器密钥，官方包无法解出。**
