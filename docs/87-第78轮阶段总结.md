## 三、当前遇到的新障碍（本轮实测）

### 障碍 1：LD_PRELOAD 会破坏渲染

- **基线（无预加载）**：vsync 3000 抓到「运行于NTSC。」，画面正常。
- **预加载 + 注入**（`INJ7: MENU pushed`）：vsync 1200/1800/2400/3000 四帧**全黑**。
- **预加载 + 不注入**（对照，`REA_INJ_DELAY=900`）：vsync 3000/3600 **同样全黑**。

**结论：黑屏是 `ld.so.preload` 本身造成的，与注入动作无关。**

推测原因：该固件的 UI 依赖固定的虚拟地址布局（大量固定物理/虚拟映射），预加载一个额外共享库改变了 mmap 分配，破坏其假设。

### 障碍 2：驱动读到了 ADC 值，但不产生按键事件

- 注入 `rear_adc` ch3 = 0x20（= MENU 的合法电平区间）；
- 模型侧记录 `[ADCRD] ch=3 val=0x0020`（驱动确实读取）；
- 但 `/proc/udm/input` 的 `get` 模式始终 `keycode:0x0`；
- 逐通道扫描 ch0–ch7 也无事件；
- `InputService::createEvent`（libObj+0x3CFAEA，基址 0x057E3000 已确认）断点**零命中**。

说明按键扫描线程虽在运行，但没有把 ADC 值转成事件。
