# 19 · kliro 线程与 av-cam 初始化序列

本轮为离线 QEMU 观测与本地静态分析，未访问相机。

## 一、kliro 线程的真实调用链（已抓到）

在 liro 线程跳板 `liro+0x0BE4` 断下，读取其参数结构体 `[r0]`：

```
[r0+0] = 0x5F4E2474   ← 目标函数 = liro 模块内偏移 0x2474
[r0+4] = 0x608FDEC4   ← 传入参数
```

因此 `liro-kliro_N` 线程执行的是 **liro 自己的 `0x2474`**，不是 av-cam 代码。

`liro+0x2474` 是工作循环，关键尾部：

```
0x2520  ldr r3, [r4, #0x4c]    ; 回调函数指针
0x2524  ldr r0, [r4, #0x48]    ; 参数
0x2528  blx r3                 ; 进入 av-cam
```

在 `0x5F4E2520` 断下读取该结构体（`r4 = 0x6452B3BC`）：

```
[r4+0x48] = 0x00000000
[r4+0x4C] = 0x635E1A6D        ; ← av-cam 内的 Thumb 函数
[r4+0x14] = 0x68AF9040
[r4+0x40] = [r4+0x44] = 0x6452B3F8
```

即 **kliro 线程通过 `[struct+0x4C]` 进入 av-cam 的 `0x635E1A6D`**。

## 二、0x635E1A6D 是 av-cam 的初始化序列

该函数逐项调用初始化例程，并在每步之间调用 `0x635E19D0(r0=0, r1=<进度 id>, r2=<序号>)` 报告进度：

```
0x635e1a72  r1=0x74, r2=0   →  bl 0x635e19d0
0x635e1a86  blx 0x63ad1278            ← 第一个真正的初始化步骤
0x635e1a8c  r1=0x89, r2=1
0x63d8198a  ...
0x635e1a9a  r1=0x96, r2=2   → bl 0x63d85b76
0x635e1aa8  r1=0xaa, r2=3   → bl 0x63a31e68
0x635e1ac4  r1=0xad, r2=4   → bl 0x63c2ef9a
0x635e1ad2  r1=0xb0, r2=5   → bl 0x63a72890 …
```

`0x635E19D0` 本身只是**构造并发送一条 0x2c 字节的消息包**（写入头部、调用 `0x635E147C`、`0x635E1980`、`0x635E19C4`、`0x635E13B8` 等），不是重试循环。

## 三、观测到的异常现象

对 `0x635E19D0` 设断点连续记录 40 次命中，**全部是同一组参数**：

```
r0 = 0x0, r1 = 0x74, r2 = 0x0, thread = 01
```

即初始化序列停留在**第一个进度点 `0x74`** 反复执行，从未推进到 `0x89`、`0x96` 等后续步骤。

这与崩溃现象一致：整个 av-cam 初始化卡在第一步，后续“等待 → 重试 → 报错”就在这条路径上发生。

## 四、尚未确定

- 为什么 `0x635E1A6D` 会被反复从 `0x74` 重新进入：是外层工作循环重复调用，还是第一步内部失败回退。
- `0x63AD1278`（第一个初始化步骤）是否返回失败并导致重来。
- `thread=01` 与之前崩溃时的 `thread=04` 的关系（多核线程编号）。
