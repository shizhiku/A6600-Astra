# 68 · 字体链表非空；注册路径待定位

本轮为离线解析与一次客户机内 shell 检查。无设备写入。

## 一、字面量修正与链表头地址

`0x54E7AC` 处 `ldr r4,[pc,#0x20]` 取到 4 字节字面量：

```
字面量地址 0x54E7D0，值 = 0x00EA7D48
add r4, pc（0x54E7B0） → PC = 0x54E7B4
链表头 VA = 0x54E7B4 + 0xEA7D48 = 0x13F64FC
运行期基址 0x057E3000 → 0x06BD94FC
```

（上一轮用 2 字节当字面量，算出 0x05D394FC，**是错的**。）

## 二、运行时读取：链表非空

在 `TextRM_loadFont` 入口下断并 dump `0x06BD94FC`：

```
REA_MEM 0x6bd94fc len=16: b0570500 00000000 00000000 00000000
```

首字 = **`0x000557B0`（非 NULL）**。

**说明系统里已经注册过至少一个字体**，只是没有 `FONT_S_CHINESE` 这一项。

同时确认入口寄存器：

```
R00 = 0x0012B8C0（字体描述指针）   R14 = 0x05E2A945（libObj 0x647945）
```

## 三、节点创建函数（字体注册）

扫描 `bl` 目标为 `0x54E7D4`（节点创建）的位置，命中 3 处：

| 位置 | 目标 |
|---|---|
| `0x54EA46` | `0x54E7D4`（创建节点） |
| `0x54ED6E` | `0x54E7A8`（查找节点，即 loadFont 内） |
| `0x54EEA8` | `0x54E7D4`（创建节点） |

即注册/创建节点发生在 `0x54EA46` 与 `0x54EEA8` 附近的两个函数中。

## 四、客户机内 shell 检查未取得结果

尝试在客户机 BusyBox 内执行：

```
ls -l /tmp/images
ls /tmp | head -20
mount | head -20
```

命令确实被 shell 接收（出现提示符与 `TMPCHECK_START`），但输出被大量 eMMC 调优警告淹没，且日志中**未见字体文件名**。本次判断 `/tmp` 是否被 tmpfs 覆盖的尝试**未成功**。

## 五、当前状态小结

- 崩溃链：`TextRM_loadFont` → 在已注册字体链表中找不到 `FONT_S_CHINESE` → 返回 -16 → `abort`；
- 字体文件已就位（`/tmp/images/`）但**未注册**；
- 注册动作由 `0x54EA46` / `0x54EEA8` 附近的函数完成，尚未定位其调用者与触发条件。

## 六、下一步

1. 反汇编 `0x54EA46`、`0x54EEA8` 所在函数，确认注册函数的入参（名字、路径、数据）；
2. 扫描这两个函数的调用者，找到“字体注册入口”；
3. 确认该入口为何未对 `FONT_S_CHINESE` 执行（文件未找到？路径不符？还是依赖副控制器数据）。
