## 三、生成器逻辑（`02-脚本/initv6_gen_tasks.py`）

运行方式（WSL）：

```bash
cd "<WORKSPACE>"
python3 02-脚本/initv6_gen_tasks.py          # 默认镜像 /root/astra/97/m1-verified/astra-m1-rwx5.img
```

可选参数：`--image <ext2镜像>`、`--tasks <tsv>`、`--records <tsv>`、`--out <header路径>`。

### 3.1 过滤规则（按任务书）

1. **`psid != 0`**：入口符号必须在 `/lib/a5bObj.so`（五代 `libObj` 合并库）的 `.dynsym` 中存在 →
   记为 `lib = NULL`，bridge 使用 libObj handle。
2. **`psid == 0` 且 `file` 以 `lib` 开头**：按 `libX.so → a5bX.so` 规则在运行镜像中查 `/lib/a5bX.so`；
   要求文件存在、且 `.dynsym` 导出该 `init` 入口 → 记为 `lib = "/usr/lib/a5bX.so"`。
3. **其余**：跳过，并记录原因码：
   - `no-init`：记录本身没有 init 入口（type1 仅 dlopen / 非库记录 / insmod）
   - `non-lib-file`：`psid=0` 且 file 不是 `lib*.so`，无法按 a5b 规则映射
   - `libobj-symbol-missing`：`psid!=0` 但 a5bObj 未导出该入口
   - `image-lib-missing`：运行镜像里缺少 `/lib/a5bX.so`
   - `image-lib-no-entry`：目标 .so 存在但未导出 entry（本轮 0 条）
   - `flag-unknown` / `image-lib-bad-elf`：兜底错误（本轮 0 条）

### 3.2 分组规则（按任务书：flag 推导）

| flag | group | 含义 |
|---|---|---|
| `0x1` | 1 | INFRA0 |
| `0x2` | 2 | INFRA1 |
| `0x4` | 3 | INFRA2 |
| `0x0F` / `0xFF` | 0 | main |

### 3.3 实现要点

- 自带最小 **ELF32 little-endian `.dynsym`** 解析（读 section header → `SHT_DYNSYM` → `.dynstr`），不依赖 pyelftools；
- 只读运行镜像：`97_ext2.Ext2` 读 `/lib` 目录、按需读出候选 .so 解析 dynsym（带缓存）；
- 输出顺序 = **118 条原厂 IMDB 表顺序**（数组内 `index` 单调递增，已校验），组内自然保持表顺序；
- 输出头部含来源/SHA/统计/跳过原因与全部跳过记录注释，便于追溯；
- 输出确定性：连续运行两次 header 字节级一致（SHA `1cfb2dd7…` 相同）。

- 头部注释内含镜像/SHA/统计/跳过原因与全部跳过记录，可审计。

### 6.3 bridge v6 运行时行为（按代码）

1. `Application_System_Init(config)`（导出名与 bridge5 保持一致，供 preload 覆盖）：
   - 先把 `config == "AdjChkConfig.so"` 翻译为 `"a5jChkConfig.so"`（与 v5 一致）；
   - `dlopen("/usr/lib/a5pFw.so", LAZY|GLOBAL|DEEPBIND)`；
   - 再 `dlopen("/usr/lib/a5bObj.so")`、`dlopen("/usr/lib/a5bMWF.so")`；
2. 按 group 顺序执行 58 条表项（数组顺序 = 原厂 IMDB 表顺序）：
   - **main 组**：当前线程依次执行（本轮 0 条）；
   - **INFRA0/1/2**：各起 1 个 pthread，组内按表顺序依次执行；3 个组并发；
   - 每一条 init 调用都放入**独立临时线程**并最多等待 **2000 ms**：超时记 `TIMEOUT` 后继续，不阻塞后续；
   - 日志格式（写 `/dev/console`）：
     - 每条：`[INIT6] g=<group> <entry> <lib> rc=<n>|TIMEOUT|SKIP`
     - 组界：`[INIT6] g=<group> <main|infra> BEGIN tasks=<n>` / `[INIT6] g=<group> END done=<n> timeout=<n> skip=<n>`
3. 三组总等待上限 **90 s**（10 ms 轮询计数），到点记 `[INIT6] infra wait cap 90000 ms reached` 后继续；
4. 全部结束后 `dlopen("/usr/lib/a5pFwBoot.so")`，`dlsym("Application_System_Init")` 并调用（用 boot handle 取符号，避免与 host/preload 的 `Application_System_Init` 冲突；与 bridge5 相同策略）；
5. 句柄缓存加 `pthread_mutex`（3 个 infra 组并发 dlopen 时避免缓存竞争）；libObj 句柄为 `lib==NULL` 项专用。

## 七、注意事项与风险

### 7.1 main 组为空（重要，需要决策）

- 118 条 before-Application 记录里 **没有一条 `flag=0xF/0xFF`**：0xF/0xFF 记录位于 A–C 段（target 定义/未启用的内核模块组），本启动路径不执行，因此不在 before 表内。
- 而阶段 D 的 7 条任务（`#28,29,30,32,35,37,39`）在原厂是 **runner=main**（stage mask 0xFF 全匹配、主线程执行），但它们的记录 `flag` 是 `0x1`（INFRA0 位）。
- 按任务书"group 用 flag 推导"，这 7 条被归入 group 1，于是 **main 组 = 0 条**；bridge 的 main 分支保留但空转。
- 若要与原厂线程语义一致（这 7 条应回主线程、先于 F 段），只需把生成器分组规则改为"`runner=='main'` → group 0，其余按 flag"，重跑生成器 + 重编译即可（一行改动，`astra97_inits` 结构不用动）。本轮**严格按任务书规格**输出，未擅自改动。

### 7.2 顺序偏差

- 原厂：D 段（7 条）在主线程先跑，然后 F 段由 3 个 infra 线程并发。
- bridge v6：main 组空 → 3 个 infra 线程启动后，g2/g3 立即开始 F 段；7 条 D 段任务位于 g1 数组最前，会在 g1 线程里先执行。**近似**原厂但非严格同步；若要严格，需要 §7.1 的 runner 分组修正 + 可选地先让 g1 跑完 D 段再放行 g2/g3（当前未实现）。

### 7.3 镜像缺口

- 46 个 `/lib/a5bX.so` 在运行镜像缺失，对应任务本轮无法执行；这是"五代初始化"最大的一块缺口（与 `imdb5_missing.tsv` / 文档 109 对照）。
- `core_sync_user_init`（#45）不在 a5bObj dynsym，也无法执行。

### 7.4 超时语义

- 每个 init 2000 ms；超时的线程**不会被取消/回收**（与 bridge5 一致，继续后台运行），后续日志可能仍出现其副作用。
- 组级 90 s 总上限只覆盖 3 个 infra 组；若某组 17~30 条全部超时，理论上组内耗时可达 34~60 s，仍小于 90 s 上限。

### 7.5 其他

- `a5bObj.so` 与五代原厂 libObj SHA 不同：入口判定以运行镜像副本为准（正确），换镜像必须重跑生成器。
- 本轮**没有运行 QEMU**，因此"58 条是否真的能跑、超时/返回码如何"仍是运行时未知；本次交付的是可编译、可复现的生成链与库。
- 运行镜像/固件/其他脚本/文档均未改动（仅新增本文档与 3 个源码/脚本 + 1 个编译产物）。
