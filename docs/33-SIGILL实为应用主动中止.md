# 33 · SIGILL 实为应用主动中止（noinit 路线终止）

本轮为离线分析。无设备写入。

## 一、关闭 ASLR 后地址稳定

内核镜像中确认存在 `norandmaps` 参数。加入 cmdline 后重跑：

| 项目 | 未加 | 加 `norandmaps` |
|---|---|---|
| 故障地址 | `0x04253796` / `0x0427C796`（漂移） | **`0x041CC796`（固定）** |
| libc 映射基址 | 随机 | `0x041B7000` |
| 故障偏移 | `0x15796` | `0x15796` |

地址已可稳定复现，便于后续下断。

## 二、关键：日志中的函数追踪

故障前日志包含调用追踪：

```
function entry : 0x041cc601 [ factor : 0x041cc796 ] -- gnu_get_libc_version @ /lib/libc-2.11.2.so : 0x15796
<- function entry : 0x041cc601 [ caller : 0x041cc796 ] -- gnu_get_libc_version @ ... : 0x15796
<- function entry : 0x041dbd65 [ caller : 0x041dbd8f ] -- raise @ /lib/libc-2.11.2.so : 0x24d8f
<- function entry : 0x00000000 [ caller : 0x00000002 ] -- ## Unknown @ NULL : 0x2
```

解读：

1. `0x041CC601` = libc 基址 + `0x15601` = `gnu_get_libc_version` 入口；
2. 该函数返回到 `0x041CC796`（即报出的故障地址，libc + `0x15796`）；
3. 随后 **`raise` 被调用**（返回地址 `0x041DBD8F`，libc + `0x24D8F`）；
4. 再往后出现 `Unknown @ NULL`。

## 三、修正结论

此前判断“CPU 处于 ARM 状态解释 Thumb 字节导致未定义指令”，**这一判断不成立**。

真实情况是：**应用自己走了 `raise`/abort 路径，主动触发 SIGILL**。内核异常监视器随后捕获该信号并停机。

因此 `0x041CC796` 不是被错误跳转到的地址，而是**主动中止时的返回地址**。

## 四、为什么应用会主动中止

该现象只在“跳过 av-cam 初始化”的诊断镜像下出现。合理解释：av-cam 未初始化 → 相关服务/接口不可用 → `im.elf` 检测到致命错误 → 主动 abort。

这与前面“av-cam 初始化是当前唯一阻塞点”的判断一致。

## 五、路线决定

**noinit 路线到此终止**：它不能作为通往菜单的可用路径，只会把确定性崩溃换成应用主动中止。

后续回到正解：让 av-cam 初始化正常完成。

## 六、下一轮重点

判据为：

```
r5 = ([obj+3] ^ (global << 4)) & 0x7F
成功 ⇔ r5 == 0
```

当前 `global = 0x04`，要求 `[obj+3]` 落在 `{0x40, 0xC0}`。

而观测到 SIO 帧第三字节序列包含 `0x00`（如 `39 0E 00 00`）。**若 `global` 为 `0`，则 `[obj+3] == 0` 的帧会让判据成立。**

因此下一轮要回答：**`global`（地址 `0x644C4E43`）由谁写、为什么是 `0x04`、在真机上是否应为 `0`。** 这是目前最有希望、且不需要设备对端模型的突破口。
