# 37 · 核实「看门狗强制 USB 模式」与「崩溃日志落 SD」

本轮为**纯静态核实**（本地固件镜像），没有在真机上制造死机。

## 一、看门狗：确证存在，且启动时已启用

### 内核实现

内核镜像中存在完整实现（`arch/arm/mach-cxd900x0/wdt.c`）：

```
wdt_proc_init   wdt_proc_ioctl   wdt.mp_excpt   wdt.timeout   wdt.mode
"Emergency interrupt!!"
"WDT:RSTREQ_STAT=0x%lx"
"WDT:ERROR:request_irq"
"watchdog: new_tick=%d"
"watchdog extended on cpu%d"
create_watchdog_if_on_cmdline
__udif_init_udif_wdt
```

关键词 `RSTREQ`（reset request）表明超时后是**向 SoC 发复位请求**，即整机复位，而不是简单杀进程。

### 启动参数确实开着

从相机实际使用的 `kemco.txt`（内核命令行）读到：

```
wdt.timeout=500
wdt.mode=1
xrstreq=
cfg.smode
```

以及 `cfg.smode` 参数（service mode 配置）——这正是“复位后进入服务/USB 模式”的开关位置。

### 与模拟器日志的呼应

模拟器启动日志中也有：

```
[2.560415] watchdog: new_tick=2000
```

说明该驱动在我们的模拟内核里同样初始化了（只是模拟器的客户机时间在 oops 后停住，看门狗不会触发）。

## 二、`60 秒` 这个数字：量级对得上，单位未证实

命令行给的是 `wdt.timeout=500`。若单位是 0.1 s → **50 s**；若是 0.125 s → **62.5 s**。两种都与“约 60 秒”吻合，但**我没有从代码里解出确切单位**，所以这一点仍属“量级吻合、数值未证实”。

## 三、日志落 SD：机制存在，路径明确；但“崩溃时强制写卡”未直接证实

### 已确证的组件

1. **`kikilog.ko`**：位于 `/usr/kmod/kikilog.ko`（已提取，33,704 B），是**内核模块**，因此天然以最高权限运行；其导出字符串含 `kikilog_proc_write`、`kikilog_dat_write`、`kikilog_get`、`kikilog_delete`、`kikilog_set_notify_cb` 等。
2. **设备节点**：`/dev/usb/kikilog`（模块与用户态通过它交互）。
3. **日志文件路径**（在 `/usr` 与内核字符串中）：
   ```
   /log/escapelog.bin      /log/blog_usb.txt    /log/mprlog.bin
   /log/ulogio_klog.txt    /log/ulogio_tlog.txt /log/TEST
   ```
4. **“GET LOG” 功能字符串**：`GET LOG: klog` 等，说明存在日志导出入口。
5. **SD 卡侧路径**：`/mnt/dcim/100msdcf`、`/android/storage/sdcard0/dcim/100msdcf`。

### 尚未直接证实的一点

我**没有找到**“发生崩溃时由看门狗/异常路径强制把日志复制到 SD 卡”的明确代码路径；现有证据只能说明：日志子系统是内核级、权限最高，并且存在 SD/DCIM 路径。

## 四、结论

| 说法 | 结论 | 依据强度 |
|---|---|---|
| 存在看门狗，超时会复位 | **确认** | 内核源码路径 + 命令行参数 + 模拟器日志 |
| 复位后可进入 USB/服务模式 | **很可能** | `cfg.smode` 参数 + 我们此前多次成功进入服务模式的事实 |
| 约 60 秒 | **量级吻合，数值未证实** | `wdt.timeout=500`，单位未知 |
| 崩溃日志强制保存到 SD、优先级高于系统 | **部分证实** | 内核级 `kikilog` + `/log/*` + DCIM 路径；缺“崩溃时复制到卡”的直接证据 |

## 五、对当前工作的意义

1. 这条信息**降低了试错风险**：即使真机死机，也有硬件复位 + USB 恢复的兜底。
2. 但我们**仍不会**为验证而故意让相机死机——上面能用静态证据确认的部分已经确认，剩下的需要实际触发才能验证，代价与收益不成比例。
3. 若将来确实需要在真机上验证，建议路径是：先确认 SD 卡内是否已存在历史崩溃日志（只读检查卡目录），这比制造崩溃更安全。
