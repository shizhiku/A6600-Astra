# 28 · oops 不可绕过；设备侧对端仍是关键

本轮为离线 QEMU 实验与一次有界只读采集。无设备写入。

## 一、崩溃后系统并未继续启动

复查真机镜像运行日志（`live-avcam-20261120T185357Z-39353`）：

```
[2.560415] watchdog: new_tick=2000
[2.560421] Internal error: : 81b [#1] PREEMPT SMP
[2.560949] PC is at 0x63858adc
...
Entering exception monitor.
Type `help' to show commands.
Type `exit' to exit.
Exception>
```

**内核进入 Sony 内置的异常监视器并停在那里等待串口输入**，所以后续启动全部停止。这是“卡住”的直接原因。

日志末尾 guest 时间停在 `2.565 s`，此后无任何进展。

## 二、尝试绕过异常处理：失败

修改 cmdline，移除 `exception.reboot=`、`exception.console_option=`、`em_console=` 三项后重跑：

| 项目 | 原始 | 移除异常参数 |
|---|---|---|
| `Unhandled fault` 次数 | 1 | **1** |
| 进入异常监视器 | 是 | **是** |
| 最后 guest 时间 | 2.565 s | 2.565 s |

该异常处理由内核内置实现，不受这三个参数控制。**此路不通。**

## 三、真机对象的快照不可直接用作期望值

读取真机 `PA 0x040E4000` 页（对应 VA `0x640E46A0`）：

```
对象内容：00 7F 21 60 C9 06 00 00 …
```

**不是 SIO 帧**。说明该缓冲在运行期被反复复用，相机空闲时的内容与启动阶段无关。**不能用它推断启动期的期望值。**

## 四、当前判断

崩溃不可绕过，必须让判据成立。判据等待的是 `[obj+3]` 变为 `0x40`（或 `0xC0`），该字节属于 SIO ch0 相关缓冲，而模拟器对 ch0 **只记录 TX、没有对端应答模型**。

与之前 ch3 副控制器的经验一致：**缺失的是设备模型，不是固件逻辑**。

## 五、下一步（按优先级）

1. **确认 ch0 的对端是谁**：检查 `sony-a6400` 机器模型里 `cxd90045.camcore-f312`（当前是读写桩）与 SGC1 相关块，判断 av-cam 是否在等 ISP/传感器核心的状态位。
2. 若确认等待的是状态位，则在设备模型中实现该状态转换（例如初始化完成后置 ready 位），这是正常的模拟器完善，而非篡改固件。
3. 若确认等待的是帧应答，则需在真机上采集 ch0 的应答缓冲（需先定位其地址）后回放。
