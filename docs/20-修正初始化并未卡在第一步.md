# 20 · 修正：初始化并未卡在第一步

本轮为离线 QEMU 观测，未访问相机。

## 一、必须纠正的上一轮结论

上一版（文档 19）称“av-cam 初始化卡在第一个进度点 `0x74`，反复重试”。**这个结论是错的**，原因是观测方法缺陷：

序列模式在断点处 `continue` 后，QEMU 又停在**同一条指令**上（PC 相同、寄存器相同），而记录代码没有跨过断点，于是把“同一个断点被反复停在原地”误读成“初始化反复重试”。

修正方式：每次命中后先撤掉断点、单步一条、再重新装回。修正后同样的观测得到完全不同的结果。

## 三、`0xD0` 之后的执行路径

`0x635E1BCC` 之后的代码：

```
0x635e1bce  r1=0xd0, r2=0xe   →  bl 0x635e19d0      ; 最后一条进度报告
0x635e1bd6  bl 0x6361fa10
0x635e1bda  pop.w {r4,r5,r6,lr}
0x635e1bde  b.w 0x635e0d40                          ; 尾调用进入主循环
```

即初始化在 `0xD0` 后结束，尾调用进入 `0x635E0D40` 的主循环；崩溃发生在之后的运行阶段，不是初始化步骤内部。

## 四、重试例程的调用方式（补充）

在回调跳板 `0x63CEFCAA` 断下，得到其调用者返回地址 `0x63D3B573`（Thumb 返回位），对应 `0x63D3B570` 的 `blx r3`。

该处属于一个**虚调用转发块**（`0x63D3B556`）：

```
ldr r4,[r0,#4]        ; 偏移/标志
tst r4,#1
asrs r3,r4,#1
ldr r5,[r0,r3]
ldr r3,[r0]
ldr r3,[r5,r3]
add r0,r0,r4,asr #1
blx r3
```

说明重试例程是通过对象虚调用进入的，符合“回调对象分派”的判断。

## 五、当前对故障的理解

- 初始化完成 → 进入主循环 → 主循环内通过虚调用进入等待/重试逻辑；
- 该逻辑要求某缓冲字节等于 `0x40`（`r5 = ([obj+3] ^ 0x40) & 0x7F == 0`），实测为 `0x04`；
- 等待超时后写状态 7、发消息 `0x3A`，随后触发显式空地址陷阱。
