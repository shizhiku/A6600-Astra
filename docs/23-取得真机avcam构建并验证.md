# 23 · 取得真机 av-cam 构建并验证

本轮包含一次只读文件采集与一次离线 QEMU 运行。无任何写入。

## 一、重大发现：我们一直用错了 av-cam 镜像

通过 Senser 文件接口直接读取相机上的 `/system/av-cam.bin`，成功取得 **16,925,472 字节**。

| 项目 | 相机实际 | 更新包（此前使用） |
|---|---|---|
| 大小 | 16,925,472 B | 16,825,940 B |
| 差值 | — | **99,532 B（`0x184CC`）** |
| SHA-256 | `812479300c47a3a2…` | `c17bdd14bb3f51ab…` |
| 头部 64 字节 | 完全相同 | 完全相同 |
| 首个差异偏移 | `0x7C` | — |
| 4 KiB 块相同数 | 1167 / 4107 | — |

结论：**相机运行的 av-cam 与更新包里的不是同一构建**（头部/入口一致、代码不同、体积大 99 KB）。

这个 99 KB 差值，与此前在真机内存上测到的累计偏移漂移（`0x1000000` 处 `-0x183F0`）高度吻合，说明此前的“分段偏移”其实是**两份不同构建的代码尺寸差异**，而不是加载器填充。

## 二、用真机镜像重跑：故障依旧

把相机实际镜像装入模拟器重跑（其余输入相同）：

| 项目 | 更新包镜像 | 相机镜像 |
|---|---|---|
| 崩溃时间 | 2.5614 s | 2.5605 s |
| 进程 | `liro-kliro_66` (pid 219) | 相同 |
| 故障类型 | page domain fault at `0x0` | 相同 |
| 故障 PC | `0x63849F30` | **`0x63858ADC`** |

两者 PC 差值 = `0x63858ADC - 0x63849F30` = **`0xEBAC`**，与真机内存测得的该区域偏移差 `-0xEBAC` 完全一致。

**这同时证明两件事：**

1. 我们的偏移测量方法正确（两种独立手段得到同一数值）；
2. **镜像构建差异不是本次崩溃的根因** —— 同一逻辑在真机构建里同样会崩。
