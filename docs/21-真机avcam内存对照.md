# 21 · 真机 av-cam 内存对照：头部吻合、深处不吻合

本轮含两次有界只读采集（每次一个 Senser 会话、固定页清单），无任何写入。

## 一、已确认的事实

### 1. av-cam 在真机上确实加载于 0x035C6000

离线解析已采集的 `Backup.bin` 属性 `0x00FA007C`：

```
0x00FA007C = 0x035C6000
```

并且属性 `0x00FA0080` 内有一张内存表，其中一项为：

```
\av-cam.bin   起点 0x035C6000   终点 0x048C5FFF
```

与模拟器使用的加载地址一致。

### 2. 内存读取本身可信

读取真机物理地址 `0x035C6000` 的一页，与本地 `av-cam.bin` 前 4096 字节比对：

```
live  : 0a0000ea 4f52494c 04000000 44605c63 ...
local : 0a0000ea 4f52494c 04000000 44605c63 ...
```

前 64 字节完全一致，整页 3181/4096 字节相同。说明读取通道可信、av-cam 确实在该地址。

### 3. 但深处内容与本地文件不吻合

按文件偏移采样 8 个页（每页 4096 字节），与本地文件同偏移比对：

| 文件偏移 | 物理地址 | 相同字节数 |
|---|---|---|
| 0x000000 | 0x035C6000 | 3181 / 4096 |
| 0x200000 | 0x037C6000 | 50 / 4096 |
| 0x400000 | 0x039C6000 | 61 / 4096 |
| 0x600000 | 0x03BC6000 | 102 / 4096 |
| 0x800000 | 0x03DC6000 | 80 / 4096 |
| 0x900000 | 0x03EC6000 | 98 / 4096 |
| 0xA00000 | 0x03FC6000 | 995 / 4096 |
| 0xAC0000 | 0x04086000 | 50 / 4096 |

而且这些页既不是全 `0xFF` 也不是全 `0x00`，是**另一份有意义的代码/数据**。例如偏移 `0x900000` 处：

```
live  : 3a3a 5365 7450 6172 616d ...   → "::SetParamSetAgc"
local : 5441 5445 5d5b 2573 ...        → "TATE][%s]: %s ->"
```

### 4. 因此此前的对照结论无效

先前把真机 `0x040D26A3` 读到 `0xFF` 当作“未初始化”，并据此推断布局不同——现在看，更可能是**真机该处的 AV-CAM 内容本身就与更新包的不同**，读取地址没有问题。

## 二、三种可能原因（尚未区分）

1. **真机的 `av-cam.bin` 与更新包中的不是同一构建**：相机当前固件与更新包的 av-cam 版本不一致。
2. **加载时重定位/解压**：liro 可能不是平铺整文件，而是按自身头部描述分段装载，导致偏移不对应。
3. **Senser 内存读取在偏移较大时语义不同**（例如按字交换或分块边界），造成伪不匹配。

## 三、下一轮如何区分

把采到的页**完整保存**后，用本地文件做全文搜索：

- 若 live 页内容能在本地文件的**另一个偏移**找到 → 说明是布局/偏移问题（原因 2）；
- 若在任何偏移都找不到 → 说明是**不同的二进制**（原因 1），那意味着我们一直在分析一份与相机实际运行的 av-cam 不同的镜像，必须更换输入；
- 若内容呈规律性字节交换 → 原因 3，读取方式需修正。

本轮脚本只计算了哈希与头部，**未保存整页数据**，因此该检验需要重做一次采集。

## 四、影响评估

如果确认是原因 1（不同构建），则：

- 之前所有基于更新包 `av-cam.bin` 的地址分析（重试例程 `0x638529D8`、判据对象 `0x640D26A0`、全局字节 `0x644AE3A5`）都需要在**真机镜像**上重新核对；
- 模拟器应改为加载与相机一致的镜像，才可能通过该判据。

这会是本轮最重要的发现方向。
