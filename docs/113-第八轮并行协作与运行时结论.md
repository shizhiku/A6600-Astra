# 113 · 第八轮并行协作与运行时结论（2026-11-22）

## 一、本轮运行时结论

### 1. 五代 init 序列已补齐（bridge5）

`infra_input_init / uxengine_init / grm_init / DDSUserInit` 等符号其实导出于**五代 libObj.so**（静态合入），不需要 ZV /usr 镜像里缺失的独立 .so。bridge5 以“每个 init 独立线程 + 2.5 s 超时”方式依次调用：

```
dmp_allocator_lib_init -> 0
dmp_allocator_mmap_init -> 0
DDSUserInit -> 0
uxengine_init -> 0
WidgetLayouter::sys_initialize -> 1
infra_input_init -> 非 0（已执行）
MWF_Init -> 非 0（已执行）
grm_init -> -1
appFwBoot::Application_System_Init -> 返回
```

镜像：`/root/astra/97/m1-verified/astra-m1-init5.img`（SHA `dc62a293...`）。

### 2. 初始化生效但渲染仍未启动

线程表新增 `uxengine_res1/uxengine_res2`、`StlDateEvtLoop`、`IWrapperBB/IWrapperBBSub/IWrapperHDMI` 等五代线程；但：

- `[VPH] ch53 still 0`、`[DMPCOUNT] draw=0`、无帧；
- `THREAD_APP` 有线程停在 `sugilite_ioctl`（GPU 驱动 ioctl 等待），另一个在 nanosleep；
- `grm_init` 返回 -1；`infra_input_init`/`MWF_Init` 返回值非 0（语义未确认）。

### 3. 输入事件仍未到五代 key_status

带 key_status 分发陷阱的 init5 运行里仍只命中 2 次（r6=0、sl=4，早期内部事件），12s/25s/40s 注入 MENU/ENTER 后无新命中。四代 `InputService::createEvent` 在 ASTRA 镜像仍 0 命中。判断：四代 InfraInput 抢先消费驱动事件、五代输入栈收不到。

### 4. 探针稳定性

render-loop 陷阱 preload 的一次运行里 `bootin.elf` 早期崩溃（无我们的 trap 日志），探针本身还可能影响启动；后续此类运行期探针要单独隔离验证。
