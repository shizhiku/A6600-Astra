QEMU 11.1.3 + sony-a6400 机器模型已在本地编译成功，使用 a6600 的官方内核、initrd、av-cam 与真实设置运行。

- `im.elf` 已执行 ✅

### 4.2 当前的停止点

停在 `av-cam.bin` 内一条**显式空地址写入**：

```
63849f24  cmp  r3, #3
63849f26  bne  63849f3c
63849f28  movs r0, #9
63849f2a  bl   63d2aaf2      ; 记录消息
63849f2e  movs r3, #0
63849f30  str  r3, [r3]      ; 主动触发致命异常
```

**尚未观察到菜单。**

### 4.3 已查清的因果链（部分）

1. 进入该分支前，固件比较一个 getter 返回值与 4；实测该值为 **7**，因此没有跳开。
2. 这个 7 由固件自己写入：某段逻辑在计数超过 29 时写状态 7 并发布消息 `0x3a`。
3. 该段逻辑的清零条件是：
   ```
   r5 = ([对象+3] ^ (全局字节 << 4)) & 0x7f
   r5 == 0            → 清零
   [状态结构+1] == 1  → 清零
   否则               → 计数加一
   ```
4. 写监视确认：**`[状态结构+1]` 在运行期从未被写过**，它唯一来源是从 `Backup.bin` 的属性 `0x00170000` 拷贝而来，真机该位置就是 0。

### 4.4 已排除的假设

| 假设 | 结果 |
|---|---|
| 缺副控制器数据是主因 | 回放真实帧后仍在同一处停止，**不成立** |
| 加 source-30 时序偏移能解决 | 结果完全一致，**无效** |
| 是设置属性 `0x00170000` 的字节 3 直接导致 | 那只是分支条件之一，**非根因** |
| 该计数稳定累加 30 次才失败 | 实测 40 次命中有清零穿插，**不成立，已撤回** |

## 五、本轮修正的方法学错误

这些错误此前污染过结论，现已修正并记录：

1. **寄存器宽度**：本机 QEMU 的 GDB `g` 包对 32 位 ARM 使用每寄存器 **4 字节**，此前按 8 字节解析，寄存器全部错位。
2. **PC 相对寻址**：Thumb 16 位 `ADD Rd, PC` 的 PC **不做 4 字节对齐**，且字面量应按 4 字节读取。修正后 `0x63852a2e + 0xC5B97C = 0x644AE3AA`，与实测一致。
3. 已做**运行代码身份校验**：断点处读取运行内存与本地文件同址字节逐字节相同，排除镜像被替换。

## 六、明确不可用的风险项

- **实验 DAT 不可刷**：包内 `part_image.sum` 仍保留原厂 CRC `520fff36`，而修改后分区实际 CRC 为 `129576f8`。解密回读成功只证明容器能解析，不证明设备接受或启动安全。
- **无回滚方案**：没有验证过的变砖恢复路径。
- **ASTRA UI 从未运行**，五代库的符号隔离与 ABI 兼容未验证。
- **垫片从未被证实调用过**。
