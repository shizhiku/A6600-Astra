# 67 · 字体加载失败的确切位置：在“已加载字体链表”里找不到

本轮为离线反汇编与一次运行时观测。无设备写入。

## 一、助手函数 0x54E7A8 的逻辑（已看清）

```
54e7a8  push {r4,r5,r7,lr}
54e7aa  mov  r5, r0          ; r5 = 字体描述指针
54e7ac  ldr  r4, [pc, #0x20] ; 取偏移
54e7b0  add  r4, pc
54e7b2  ldr  r4, [r4]        ; r4 = 链表头
54e7b4  b    0x54e7c8
54e7b6  add.w r0, r4, #8     ; 节点+8 = 名字字符串
54e7ba  mov  r1, r5
54e7bc  mov.w r2, #0x100     ; 256 字节
54e7c0  blx  0x101868        ; 字符串比较
54e7c4  cbz  r0, 0x54e7cc    ; 相同 → 返回该节点
54e7c6  ldr  r4, [r4]        ; 下一个
54e7c8  cmp  r4, #0
54e7ca  bne  0x54e7b6
54e7cc  mov  r0, r4
54e7ce  pop  {r4,r5,r7,pc}
```

即：**遍历一条「已加载字体」链表，按名字（最多 256 字节）比较**，命中返回节点，否则返回 NULL。

## 二、`TextRM_loadFont` 把它当成“必须已存在”

```
54ed6e  bl   0x54E7A8
54ed72  mov  r4, r0
54ed74  cbz  r0, 0x54EDC2    ; 找不到 → 错误分支
...
54edde  mvn  r5, #0xf        ; 返回 -16
```

**找不到节点就报错返回 -16**，上层 `libObj` 据此 `abort()`。

## 三、运行时观测

在 `TextRM_loadFont` 入口（运行期 `0x05D31D58`）下断，成功命中：

```
R00=0x00130C20  （字体描述指针）
R01=0x118A615C  （输出句柄）
R14=0x05E2A945  （调用者，libObj 0x647945 附近）
```

但尝试 dump 链表头（按 `libObj+0x5564FC` = `0x05D394FC`）返回 **unreadable**，说明该地址推算有误——字面量取值方式（4 字节 vs 2 字节、PC 对齐）还需再核。

## 四、当前完整因果链

```
UI 请求 FONT_S_CHINESE
   ↓
libObj::TextRM_loadFont
   ↓
0x54E7A8：在“已加载字体链表”中按名字查找
   ↓
未找到（NULL）→ 返回 -16
   ↓
libObj 错误上报 → abort() → Sony 监视器停机
```

**关键结论：字体“有没有文件”不是决定因素，真正缺的是「字体被注册进链表」这一步。**

## 五、下一步

1. 精确解析 `0x54E7AC` 处的字面量与 `add r4,pc` 的 PC 值，得到真实链表头地址；
2. 找到**向该链表插入节点**的函数（节点创建代码在 `0x54E7D4` 附近：分配 0x314 字节、写入名字、链接到表头），
   再通过扫描 `bl` 目标定位其调用者；
3. 那个调用者就是“字体注册”入口，确认它依赖什么（文件扫描、副控制器数据、还是配置表）。
