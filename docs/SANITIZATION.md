# 脱敏说明（SANITIZATION）

本仓库在归档时对原始工作区做了两类脱敏。这里说明**改了什么**、**为什么**、**如何自行恢复**。

## 一、个人绝对路径 → 占位符

原始记录里大量出现作者本机的绝对路径。公开前已统一替换：

| 占位符 | 原意 |
|---|---|
| `<WORKSPACE>` | 主工作区根目录（a6600 固件破解工作区） |
| `<WORKSPACE_MENU92>` | 第二阶段"菜单打通"工作区 |
| `<LEGACY_WORKSPACE>` | 更早的一个工作区目录 |
| `<UPDATER_DIR>` | 存放官方更新器 exe / `BODYDATA.DAT` 的下载目录 |
| `<HOME>` | 用户主目录 |
| `<user>` | 用户名（出现在说明性文字中时） |

另有少量文档中的示例路径写作 `<HOME>\…`，那是**示例**，不是脱敏残留。

**影响**：脚本不能直接运行，需要你把占位符替换成自己的真实路径。
这是有意为之——避免任何人直接对着作者环境"一键执行"。

## 二、固件解密密钥 → 占位符

原始工具（`decrypt_*.py`、`repack_*.py`、`build_full_image.py` 等）中含有 AES 密钥字面量。
本仓库**不分发密钥**，已替换为：

```python
KEY_AES = bytes.fromhex("REDACTED_KEY_AES_ECB")
KEY_K8  = bytes.fromhex("REDACTED_KEY_K8_ZV1M2")
```

占位符组成：

| 占位符 | 用途 |
|---|---|
| `REDACTED_KEY_AES_ECB` | FDAT 首块 AES-ECB |
| `REDACTED_KEY_CXD90045` | a6600 / CXD90045 平台 FDAT 链 |
| `REDACTED_KEY_CXD90057_K8` | CXD90057（五代）平台 |
| `REDACTED_KEY_CXD90014` | CXD90014 平台 |
| `REDACTED_KEY_K8_ZV1M2` | ZV-1M2 FDAT 链 |

**注意**：这些占位符不是合法 hex，直接运行会抛 `ValueError`——这是**故意的**，
以便第一时间暴露"你没有提供密钥"，而不是静默产生垃圾数据。

**影响**：任何涉及解包/重打包的脚本都需要你自己提供密钥才能运行。

## 三、为什么不直接删掉这些脚本？

因为它们是**方法的一部分**：FDAT 的分帧结构、块校验和算法、首块 ECB + 后续 CBC 链、
DEND CRC 重算、tar 重建顺序……这些才是研究的价值所在。密钥只是一个输入参数。

## 四、其他删减

| 内容 | 处理 |
|---|---|
| 个人信件草稿（索要密钥的对外邮件） | 删除 |
| 运行日志原始文件 | 未纳入（体积 + 设备细节） |
| 第三方项目源码副本 | 未纳入（改用链接致谢） |
| 早期二进制产物（`.so`/`.bin`/`.tar`） | 未纳入 |
| 临时输出 `*_out.txt`、`__pycache__` | 未纳入 |

## 五、自行恢复的边界

你可以用自己合法取得的密钥填回占位符，使脚本恢复功能。但请注意：

1. 不要把你恢复后的含密钥版本提交回本仓库（`check_repo_hygiene.py` 会拦截）；
2. 不要在 Issue/PR 中粘贴密钥；
3. 密钥的使用受当地法律约束（规避技术保护措施相关条款）。

## 六、发现遗漏

如果你发现仍有未脱敏的路径、密钥或个人信息，请开 Issue
（**只写文件路径与类别，不要贴内容**），我们会立即处理。
