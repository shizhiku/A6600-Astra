# 22 · 决定性问题：av-cam 的加载布局不是平铺

本轮基于一次有界只读采集（13 页，数据已保存）与本地离线比对。

## 一、结论

**真机上运行的 av-cam 与我们本地的 `av-cam.bin` 是同一份二进制**，但内存中的布局相对文件有**分段填充**，各段偏移量不同。

### 1.1 可靠的字符串证据（优先采信）

直接把真机页里的可打印字符串在本地镜像中搜索：

| 真机页偏移 | 字符串命中 | 本地位置 | 偏移差 |
|---|---|---|---|
| `0x900000` | 20/20 | `0x8EEC28` | `-0x113D8` |
| `0x1000000` | 5/5 | `~0xFE823B` | `~-0x17DC5` |
| `0xC00000` | **0/6** | 未找到 | — |

例：真机 `0x900000` 处的 `::SetParamSetAgcLink err %x`、`[ADF][ADJ]AdfSenserCtrl::SetPara` 都能在本地 `0x8EEC28` 附近找到。

### 1.2 页内一致性过滤后的偏移差（当前最可靠）

用 256 字节窗口 + 唯一性检查 + **页内一致性过滤**（同一页内所有命中必须给出相同偏移差）：

| 真机偏移 | 偏移差 | 页内一致命中 |
|---|---|---|
| `0x00200000` | `-0xEBAC` | 1/1 |
| `0x00400000` | `-0xEBE8` | 7/7 |
| `0x00600000` | `-0xEE08` | 9/9 |
| `0x00800000` | `-0x10F3E` | 9/9 |
| `0x00900000` | `-0x113D8` | 60/60 |
| `0x01000000` | `-0x183F0` | 60/60 |

**页内 100% 一致**，说明每个区域内部是刚性平移；但**区域之间偏移量不同**，累计到 `0x1000000` 时已达约 99 KB。

这确认了“分段填充”模型：内容相同、位置不同。

### 1.3 早期短窗口测量的偏差

先前用 32 字节 / 128 字节窗口得到过 `-0xEC58`、`0x0` 等值，与上表不一致。原因是短窗口在镜像中会命中重复代码片段。**以 1.2 的表格为准。**

## 二、这解释了此前的困惑

1. 之前读到 `0x040D26A3`（对应文件偏移 `0xB0C6A3`）为 `0xFF` —— 因为真机在该处放的是**别的内容**（布局已偏移约 `0x11000+`）。
2. 之前“深处内容与本地不符” 是因为**按文件偏移直接取页**，没有考虑填充。
3. 头部页 `0x035C6000` 匹配度高，是因为该区域偏移为 0。

## 三、对模拟器的直接影响（重要）

当前模拟器用 `-device loader,file=av-cam.bin,addr=0x035C6000,force-raw=on` **平铺加载整文件**，等价于“偏移差恒为 0”。

但代码内部的绝对地址是按**带填充的真实布局**链接的。因此：

- 前期代码（偏移为 0 的区域）运行正常，所以 `entry_pre` / `entry_main` 能完成；
- 后期地址读到的数据就错位了，包括判据对象 `0x640D26A0` 与全局字节 `0x644AE3A5`。

**这很可能就是“等待 0x40 永远等不到”的根因方向**：模拟器把结构体放在了错误的位置。

## 四、尚未确定

- 填充的具体规则：是段对齐（4 KiB / 64 KiB）还是 `av-cam` 头部描述的多个区段（ramBase / bssBase / tailBase / limitBase）分别装载。
- 本地文件头 `0xB4` 处的区段描述字段尚未正确解码（字段顺序或宽度可能不是简单的 8×u32）。

## 五、下一步（本轮更新）

### 已验证可行的
- 4 KiB 页读取稳定可用，页内一致性方法可靠。

### 已验证不可行
- **大块读取（128 KiB）会触发 USB 写入错误**，设备随后回到大容量存储但读取失败。不要再用大块读取。

### 下一轮计划

1. **静态优先**：liro 的 `.init.text` 中确认存在字符串 `%llx -> %p : %x %x loaded (%s)`，它按段打印加载信息。定位其调用点即可还原段表；但需注意 `liro.ko` 是 ET_REL，所有节 `sh_addr` 为 0，运行时地址由重定位决定，不能用节基址做 PC 相对计算。
2. **动态补充**：如需更多采样点，用 4 KiB 页、每次会话不超过约 13 页，间隔 0x40000 做若干次，逐步逼近分段边界。
3. 得到段表后，改写模拟器加载方式并重跑原厂固件验证判据。
