# 100 · 面板像素格式修正：RGB565 → RGBA4444

日期：2026-11-22。只修正离线捕获/显示端解码，不改固件、不写设备。

## 一、问题

交互演示和早期截图都偏蓝/偏紫：黑色背景发深蓝，白色文字发粉紫，“NO CARD”发洋红。此前 `rea_fb_dump()` 一律按 RGB565 解码：

```
r = ((v >> 11) & 0x1f) << 3
g = ((v >> 5)  & 0x3f) << 2
b = ((v)       & 0x1f) << 3
```

## 二、证据：同屏像素在两种格式下的解释

从原厂菜单帧 `run-20261121T153655Z-front-2/fb.2.ppm` 统计出的原始 16 位值：

| 区域 | 原始 16 位 | RGB565 解码（旧） | RGBA4444 解码（正确） |
|---|---:|---|---|
| 菜单背景 | `0x000F` | (0, 0, 120) 深蓝 | (0, 0, 0) 黑 |
| 普通文字 | `0xDDDF` | (216, 184, 248) 粉白 | (221, 221, 221) 浅灰 |
| 二级文字 | `0xBBBF` | (184, 116, 248) 紫 | (187, 187, 187) 灰 |
| 选中行 | `0x930F` | (144, 96, 120) 暗粉 | (153, 51, 0) 橙色 |
| 深色行 | `0x222F` | (32, 68, 120) 蓝 | (34, 34, 34) 深灰 |

规律：这些 UI 颜色的低半字节恒为 `0xF`，把低 4 位当蓝色分量就会给整屏加蓝；真实布局是 `R[15:12] G[11:8] B[7:4] A[3:0]`，即 **RGBA4444**。选中行 `0x930F` 正是索尼菜单的橙色高亮。

## 三、修正

`hw/misc/cxd90014_vph.c` 的 `rea_fb_dump()` 增加 `REA_FB_FORMAT=rgba4444`：

```
r = ((v >> 12) & 0xf) * 17
g = ((v >> 8)  & 0xf) * 17
b = ((v >> 4)  & 0xf) * 17   /* alpha 忽略 */
```

交互演示脚本默认设置该变量；旧的 RGB565 路径保留，未设置变量时行为不变。

## 五、边界

- 该格式结论来自同一帧的像素统计与语义配色（黑底、灰字、橙高亮），未用真实相机屏幕逐像素校准 gamma；不同 UI 主题若有半透明混合，仍需按 alpha 处理。
- 仅修正捕获侧显示。模拟器内部渲染与真实面板的差异仍需后续用真机截图对照（不在本轮范围）。
