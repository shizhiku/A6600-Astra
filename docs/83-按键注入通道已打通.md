# 83 · 按键注入通道已打通（前面板位 / 后部 ADC），但 UI 仍不整帧绘制

本轮为 QEMU 模型扩展与实验。无设备写入。

## 一、新增能力：模拟器内按键注入

模型里原本已有"把按键写进合成的 submicro 槽 A 帧"的逻辑（`out[28] |= front_pressed & (BIT1|BIT2)`），但缺少驱动入口。本轮补上两个按虚拟时间调度的注入器：

- `REA_FRONT_BTN="bit1,bit2,..."` + `REA_FRONT_T0`：前面板按键位，每 5 s 一个候选、按下 1.5 s；
- `REA_ADC_SEQ="ch:level,..."` + `REA_ADC_T0`：后部 ADC 按键电平，同样按时隙扫描。

另外把 submicro 帧文件通过机器属性 `submicro-frames=` 传入，并开启 `rear-controls=on`，使按键位真正进入回放的槽 A 帧。

## 二、实测：按键确实被 UI 接收

前面板位注入：

```
[KEYINJ] press 0x0002 slot 0 at 20042 ms
[KEYINJ] press 0x0004 slot 1 at 25002 ms
[KEYINJ] press 0x0200 slot 2 at 30012 ms
[KEYINJ] press 0x0006 slot 3 at 35022 ms
[KEYINJ] press 0x03ff slot 4 at 40033 ms
```

GPU 侧由 **19 次 `p3d-list` 变为 20 次**（多出一条 `p3d-list addr=0x205493c0 n=4`）——**说明按键事件确实被 UI 处理了**，但只提交了一条 4 项的小命令表，没有触发整帧绘制。

后部 ADC 电平注入同样生效：

```
[ADCINJ] ch3 level 45 slot 0 ...
[ADCINJ] ch3 level 182 slot 1 ...
[ADCINJ] ch3 level 356 slot 2 ...
[ADCINJ] ch3 level 520 slot 3 ...
```

但 GPU 侧无变化。

## 三、当前仍未解决

- UI 始终没有整帧绘制：仍是「清屏（fill 0）+ 整屏 PPF 拷贝」，没有任何 draw kick（reg 0x202）；
- 按键能被接收，但不足以让 UI 进入持续绘制状态。

## 四、已排除的可能性（本轮新增）

- ❌ QMP `send-key`：QEMU 无显示控制台，事件送不到机器输入处理器（`send-key` 返回成功但模型收不到）；
- ❌ 用户态 LD_PRELOAD：UI 运行在 LIRO 内核任务里，用户进程都不映射 `libObj.so`；
- ❌ 仅前面板按键位就能触发绘制：5 种位组合都只多一条命令表。

## 五、下一步

1. 用 QEMU 断点钩住 `input.ko` 的按键扫描函数（模块基址 `0x5f07c000`，取自 `/proc/modules`），确认注入的按键是否被驱动真正采到并转成 OSAL 消息；
2. 若驱动已收，则问题在 UI 的"未进入就绪状态"，需找就绪判据；
3. 若驱动未收，则需补 ADC/GPIO 侧的模型细节（当前 `cxd90014_adc_set` 可能未接到 input.ko 读取的寄存器）。
