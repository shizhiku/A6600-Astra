# 14 · a6600 副控制器页采集及离线回放

## 范围与许可

本轮先通过系统内的 USB 枚举确认相机在 MSC，再按用户批准切换一次到 Senser。没有执行相机终端命令、写文件、写内存、改 Backup 属性或扫描地址范围。

通过 PMCA `SonySenserCamera.readMemory(base, size)` 从主机直接读取一个候选 4 KiB 页：`base=0x03443000`, `size=4096`。没有在相机上创建 `/tmp_bt` 文件。读完 Senser 返回 `Done`，USB 随后重新枚举成 MSC `054c:0d0e`。

页地址来源：a6400 已有 E0526/E0527 证据指出同一 `0x03443000` 页包含 SIO ch3 RX/TX 缓冲；a6600 启动参数中的 `wbimem=0x500000@0x03085000` 也覆盖该页。本次在 a6600 上首次直接观察帧形态，因此页中缓存的身份由 CRC/类型及 QEMU 请求对应作支持；不外推其它不同运行或其它机型地址。

## 捕获结果

本地文件：`a6600_port/captures/submicro-candidate-20261121/page-0x03443000.bin`。

- 大小：4096 B
- SHA-256：`0025b2a95a4004e19033f957373efa63685d34e99f8ac6ccea8350e029b9c175`
- 三个预期 RX slot 都在候选偏移：A `+0x3a4`、C `+0x424`、B `+0x4a4`。
- Slot A 类型 `0x20`，CRC 通过；byte 28 为 `0x01`。其键语义在 a6600 上尚未独立确认。
- Slot C 类型 `0x60`，CRC 通过。
- Slot B 类型 `0x30`，CRC 通过；TLV byte-count `0x70`。现有协议解码器识别到 TLV 0/1/2/3/0x0a/0x0b/0x10/0x14。仅 ID/长度/数据是观测；部分 TLV 语义仍依赖其它机型对照。
- 同页 TX Slot B `0x31` 及 TX Slot A `0x21` 当时 CRC 无效，可能是页面快照与写操作交错，不能当有效请求帧。TX Slot C `0x61` CRC 有效。
- 这证明候选页中含格式正确的原始接收帧；不表示它们代表所有运行时刻，页面是一次性快照。

采集回执、逐页离线解析和 RX-only 回放文件回执在同目录：`receipt.json`、`page-analysis.json`、`decoded-frames.json`、`replay-receipt.json`。只读采集脚本位于 `a6600_probe/capture_submicro_candidate.py`。

## RX-only 回放

从捕获页仅提取 A/C/B 三个 RX 帧，组成 384 B 输入，不包含同页 TX 帧：

- 文件（WSL 私有 QEMU 输入）：`/root/qemu_in/a6600-submicro-frames-20261121.bin`
- 大小 384 B，SHA-256 `c1d9c5db51e8d60e1a174745a5c8ee964aeeccdb2581583c5e3b8ae384a41cd8`
- QEMU 参数：`-M sony-a6400,submicro-frames=/root/qemu_in/a6600-submicro-frames-20261121.bin`
- 原厂 `/usr`、同份真实 Backup/kemco/ulogio/DmmConfig，独立 qcow2 overlay；硬件断点停在原始 fault PC 前，没有改指令或寄存器。

**结果：并未越过故障。** 回放版仍停在 `0x63849f30`，`r3=0`；相关运行状态仍为 `r7+2=3`，被观测的 getter 标志仍为 `1` 与 `0`。到断点前 SIO ch3 仍有 4 次 128 B `0x31` 请求；QEMU 属性确已载入捕获帧。无帧输入基线也停在相同 PC，状态值相同。两次日志和完整 observation JSON 见：

- 无输入基线：`a6600_port/emulation/observe-20261120T162220Z-30354/`
- 捕获 RX 回放：`a6600_port/emulation/observe-20261120T170107Z-32451/`
- 第一次回放停在 PC 后，回执序列化器报错；保存为失败记录：`a6600_port/emulation/replay-serialization-failed-20261121/`。修复 JSON Path 类型后重跑，第二次得到完整回执。

## 结论

对这三个静态 RX 帧的回放，**不足以改变原厂故障状态**。这削弱“只有副控制器无响应导致故障”假设，但不能否认时序、动态帧字段或尚未建模的其他硬件/初始化路径仍有影响。不要把这次回放说成已验证 UI 的完整副控制器模型。

设置属性 `0x00170000` 的含义仍未知；本轮未改相机设置。没有刷机，实验 DAT 仍不可刷。

## 采集后设备状态与检查限制

USB 枚举回到 MSC `054c:0d0e`。Senser 文件协议读 `/proc/uptime` 曾返回空数据；当前 always-on debugger 的只读 ping 在 MSC 报 SCSI illegal request，所以本轮没有有效的 `/proc/uptime` 单调性或 debugger PONG 复核。保留这一健康检查缺口；没有为补检查再切换模式或扩大操作。
