## 三、已确认事实

### 3.1 启动与框架

- 内核 `3.0.27_nl-rt106+`，4 核 Cortex-A5（CXD90045）。
- `im.elf` 是**用户态进程**（PID 144，172 线程），映射 `/usr/lib/libObj.so`；`norandmaps` 下基址固定 `0x057E3000`。
- LIRO / av-cam 是内核侧任务；av-cam 的等待判据与 SIO ch0 帧计数相关（详见 01–45 号文档，含已撤回推断）。
- `Backup.bin` 属性 `0x00170000` 的 byte[2] 由 `3` 改 `1` 可绕开 av-cam 主动 panic（**诊断手段，非修复**）。
- `/proc` 下有索尼专有节点：`liro`、`osal`（目录，含 `uipc`/`minfo`）、`udm`（目录，驱动调试入口）、`vtp`、`hwp`、`klog` 等。

### 3.2 字体（已彻底解决，无需改代码）

- `Backup.bin` 属性 **`0x810000`** = `/usr/share/app/fontlist.dat`（64 字节字符串）。
- 字体注册由 libObj 的一次性初始化完成：`0x54F3A0 → 0x54E94C`，读 `Backup_read(0x810000)` → `fopen` → 逐行解析 `name/path/id/flag`。
- **注册阶段不检查字体文件是否存在**；`TextRM_loadFont` 阶段才 `fopen`。
- 因此：把真机 `/tmp/images` 的三个字体文件放好，**用原厂未改的 `/usr` 启动就不崩溃**。
  - `MYingHeiC-GB18030-SJ_wIcon.ltt`（1,958,432 B）
  - `MYingHeiC-Big5-SJ_wIcon.ltt`（1,150,740 B）
  - `Sony_DI_Icons.ttf`（545,464 B）
- `ux::core::TextLayout::registerFontFaceFile`（libObj+`0x63E2DC`）是**死代码**：全库 0 调用者、无指针表引用。

### 3.3 显示与 GPU

- VPH ch53 已编程：640×480、双缓冲（`lb=0x500`、`lines=480`），持续跑到 vsync 3600+。
- `hw/display/dmp_smaph.c`（DMP SMAPH-S30 / Sugilite）模型可用：
  - PSC 填充（`psc-fill`）、整屏拷贝（`ppf-transfer`/`ppf-copy`）、P3D 命令表与软件光栅化；
  - **draw kick 实测 100+ 次**（去掉 24 条共享日志配额后统计）。
- 帧缓冲导出：`REA_FB_PATH` + `REA_FB_VSYNC`（支持逗号列表多帧）→ PPM（640×480 RGB565 解码）。
- 画面证据：
  - `03-证据/模拟器运行/fb_base.png` —— **「运行于NTSC。」中文界面**
  - `fb_menu.png` / `fb_click.png` —— **拍摄 OSD：`NO CARD` + 中央对焦框**

### 3.4 按键与输入驱动

- 输入驱动 `input.ko`（33,768 B）加载于 `0x5f07c000`，扫描线程 `kbd_timer_hndlr` 偏移 `0x21e4`（断点确认在跑）。
- 调试接口：**`/proc/udm/input`**，支持 `table | get | adc | front | gpio | vgrip | multi_selector_soft`。
- 完整键表（`table` 模式实读）：

```
*** ADC KeyConfig ***
ID: 0-1  port: f-0    0/ 5b 10[ms] 1[jif] H2 key: 1ac-1   ← MENU
ID: 0-1  port: c-0    0/ 5b              H2 key: 1f8-1   ← PLAY
ID: 0-1  port: d-0    ...                H2 key: 70e7-1 / 66-1
ID: 0-1  port:10/11-0 ...                H4 key:7025-x   ← 多向选择器
*** GPIO KeyConfig ***  key 70fd/70fe/70dc/70c6/70ef/4b/4c/4d/47
*** FRONT(CA) ***       key 2/1f7/1ab/70d5/7094
```

- **MENU = `0x1AC`，ADC 全局端口 `0x0F`，有效电平 `0x00–0x5B`。**
- ADC 注入链路已验证可达驱动：`[ADCRD] ch=3 val=0x0020`（模型侧日志）+ `adc` 模式显示 `Ch1:Port 3 0020`。
- `/etc/ld.so.preload` 机制可用（ARM .so 可被加载，无符号错误）。

### 3.5 工具链与产物

- QEMU 11.1.3 自建机型 `sony-a6400`，编译在 `/root/qemu-11.1.3/build/qemu-system-arm`。
- 自定义钩子（默认关闭）：`REA_BP_VA`（TCG 命中 + 寄存器转储）、`REA_BP_MEMREG/MEMLEN`、`REA_BP_MEMSTR`、`REA_BP_DEREF`、`REA_KEY_LOG`、`REA_FRONT_BTN/T0/T1`、`REA_ADC_SEQ/HOLD`、`REA_FB_PATH/VSYNC`、`REA_DMP_DUMP`。
- ARM 交叉编译：`arm-linux-gnueabi-gcc -std=gnu11`；**只能用 GLIBC_2.4 级符号**（相机 glibc 2.11），否则会因 `GLIBC_2.34`（`dlsym`）/`GLIBC_2.38`（`__isoc23_strtol`）加载失败。

## 四、已撤回的错误结论（不要重复）

| # | 曾经的结论 | 实际 | 撤回依据 |
|---|---|---|---|
| 1 | UI 运行在 LIRO 内核态 | **用户态进程**，172 线程 | `/proc/144/maps` 映射 libObj |
| 2 | UI 从不提交 draw kick | **100+ 次** | 去掉 24 条日志配额后计数 |
| 3 | 19→20 条命令表证明按键被处理 | 计数被截断的误判 | 同上 |
| 4 | 字体需调用 `registerFontFaceFile` | 该 API 是死代码 | 全库 0 调用者 |
| 5 | 字体来自副控制器回调 | 只需文件存在即可 | 放字体后不崩溃 |
| 6 | `/var/fifo/sen_host_*` 是副控制器通道 | 废弃，无进程打开 | 钩子零命中 |
| 7 | 按键走 `/dev/input/event*` | UI 从不打开 | open/openat 钩子零命中 |
| 8 | `sdhci.debug_quirks2` 可修 eMMC 停滞 | Sony 自有 `AL_EMMC_SEQ` 不读该参数 | 补丁后才根除 |
| 9 | 内核禁用 syscall 191 导致 SIGILL | 应用主动 `abort()` | 50 号文档 |
| 10 | 改 `/usr` 内容必然导致启动卡住 | 实为 eMMC 调优停滞（现已修） | 补丁后 3/3 正常 |
