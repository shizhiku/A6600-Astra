# 69 · 字体注册只发生一次；最终状态汇总

本轮为离线解析与两次 QEMU 观测。无设备写入。

## 一、注册函数定位

| 项 | 地址（libObj 偏移） |
|---|---|
| 节点创建（内部） | `0x54E7D4` |
| 查找（内部） | `0x54E7A8` |
| **注册函数（大函数，栈 0x124）** | **`0x54E94C`** |
| 注册函数唯一调用点 | `0x54F42C` |
| 字体链表头 | `0x13F64FC`（运行期 `0x06BD94FC`） |

## 二、运行时观测

### 1. 在 `TextRM_loadFont` 入口（`0x05D31D58`）

```
R00 = 字体描述指针（含 "FONT_S_CHINESE"）
R14 = 0x05E2A945（libObj 0x647945）
```

同时读取链表头 `0x06BD94FC` → 首字 `0x000557B0`（**非 NULL**，已有字体被注册过）。

### 2. 在注册函数入口（`0x05D3194C`）

**命中 1 次**：

```
R00 = 0x0004F3A0   （某个对象/描述结构）
R01 = 0x00000000
R02 = 0xFFFFFFFF
R03 = 0x06BD954C   （紧邻字体链表头，疑似新节点）
R14 = 0x05D32431   （返回地址，libObj 0x54F431）
```

按 `R0` dump 内存：内容基本为 0，未见名字字符串。

## 三、结论

- 字体注册**只发生一次**，且未涵盖中文；
- 注册函数唯一调用点在 `libObj + 0x54F42C`；
- `TextRM_loadFont` 在链表里找不到 `FONT_S_CHINESE` → 返回 -16 → `abort()`。

**即：字体注册的触发条件不是「fontlist.dat 里列了就会注册」，而是由特定调用路径逐个注册；中文那一路在模拟环境中没有被执行到。**

## 四、本次会话已确认的完整阻塞链（按时间顺序）

1. av-cam 等待副控制器 SIO 帧状态 → 触发主动 panic（用 Backup 状态改值可绕开，属诊断输入变化）；
2. 绕开后 UI 框架 `im.elf` 启动，加载 `image_cmn_169.uxc` 等资源；
3. `libObj` 在 `TextRM_loadFont` 处因字体未注册而 `abort()`；
4. 崩溃被 Sony 异常监视器捕获，打印 “Illeagle Instruction”（实为 `raise(SIGABRT)`）。
