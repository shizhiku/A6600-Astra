# 121 · 真机接入事故记录与驱动体检（2026-11-22）

## 一、事故经过

| 时间 | 事件 |
|---|---|
| 05:44 | 我为只读识别执行 `usbipd attach --wsl --busid 1-2`，把相机（`054c:0d0e`，`ILCE-6600`）接到 WSL |
| ~05:59 | 用户在 Windows 侧执行「一键刷入」，相机提示 **「请检查所链接设备」** |

## 二、根因

相机被绑定到 **usbipd 的 USBIP 驱动**上，Windows 侧无法用标准大容量存储驱动枚举它：

```
Instance ID : USB\VID_054C&PID_0D0E\CFD19056970C
Description : USBIP Shared Device
Manufacturer: Oracle Corporation
Driver Name : oem215.inf
Status      : Started
```

表现：
- 设备存在但由 `oem215.inf`（USBIP）持有，不是 `USB 大容量存储设备`；
- WSL 侧 `lsusb` 也看不到它（attach 已断开但 bind 未解除）；
- 相机看到 USB 连接但主机未完成正常枚举 → 报「请检查所链接设备」。

**这不是 libusb-win32 的问题**，是我把设备 bind 到 usbipd 后没有解绑就交给了用户操作。

## 三、处置

以管理员身份执行：

```powershell
usbipd unbind --busid 1-2
```

结果（已验证）：

| 项 | 之前 | 之后 |
|---|---|---|
| `usbipd list` 状态 | `Shared (forced)` | **`Not shared`** |
| 设备 FriendlyName | `USBIP Shared Device` | **`USB 大容量存储设备`** |
| Status | Started | **OK** |
| Driver Name | `oem215.inf` | 标准 USB 存储驱动 |

## 四、教训与今后约束

1. **真机 USB 操作前必须先与用户确认**，不能自行 attach/bind，尤其不能在用户可能同时操作相机时进行；
2. 若必须接入 WSL，用完立即 `usbipd unbind` 归还 Windows；
3. usbipd-win 会在 Windows 上累积 `oemXX.inf` 驱动包（本次为 `oem215.inf`），这是该项目文档提到的已知问题；后续可做一次只读体检列出全部 `oemXX.inf` 与 Sony 相关绑定；
4. 「请检查所链接设备」这类相机侧报错，优先排查**主机侧驱动绑定状态**，而不是先怀疑相机或数据线。

## 五、关于 libusb-win32 的判断

用户转述社群经验：一键刷入失败多与 libusb-win32 驱动有关，且容易导致电脑无法识别相机或相机卡死。

本次事故**不是** libusb-win32 造成的（是 usbipd bind），但社群经验仍然成立，值得在部署前做两项只读检查：

1. `pnputil /enum-drivers` 列出所有第三方 USB 驱动，确认 Sony 设备没有被绑到 `libusb-win32`/`WinUSB`；
2. `Get-PnpDevice` 确认 Sony 设备当前驱动为「USB 大容量存储设备」。

这两项都不写入相机。

## 六、边界

本文件只记录主机侧（Windows/WSL）USB 驱动状态与处置，**未对相机做任何写入**。
后续任何真机操作仍须用户逐次明确授权。
