# 86 · 原厂 UI 已渲染（含中文），并撤回三项旧结论

本轮为 QEMU 计数修正、对照实验与画面捕获。无设备写入。

## 一、决定性结果：原厂 UI 完整渲染

**基线运行（不做任何按键注入）**，在 vsync 3000 抓帧，得到完整画面：

- 640×480 全屏绘制
- 蓝色背景 + 白色边框
- 正中显示 **「运行于NTSC。」**（中文，字体渲染正常）

证据：`03-证据/模拟器运行/fb_base.ppm` / `fb_base.png`

另一组运行（按住/点击 MENU）在 vsync 2400 抓到拍摄 OSD：

- 左上角 **`NO CARD`**（粉紫色文字）
- 中央对焦框、水平线等 OSD 元素

证据：`fb_menu.png`、`fb_click.png`

**结论：显示控制器 → GPU 光栅化 → 字体 → 中文文本布局 → OSD 合成，整条链路在模拟器里都是通的。**

## 二、撤回三项旧结论

### 1. "UI 在 LIRO 内核态" —— 撤回

82 号文档的结论错误。运行时晚期采样显示 `im.elf`（PID 144）确实映射 `/usr/lib/libObj.so` 且有 172 个线程；先前 preload 构造函数在 dlopen 完成前采样 `/proc/self/maps`，导致误判。

### 2. "UI 从不提交 draw kick" —— 撤回

原因：`hw/display/dmp_smaph.c` 的 `dmp_job_log` 使用 `static int left = 24` 的**共享日志配额**，P3D/PPF/PSC 共用，第 24 条之后全部静默。

本轮去掉该限制并加入独立计数后，实测：

```
[DMPCOUNT] draw=0    list=1   ppf=0  copy=0   psc=0
[DMPCOUNT] draw=50   list=59  ppf=9  copy=66  psc=6
[DMPCOUNT] draw=100  list=87  ppf=15 copy=110 psc=7
```

**draw kick 在持续发生（100+ 次）。**

### 3. "19 条变 20 条证明按键被 UI 处理" —— 撤回

同一原因：日志配额截断导致计数失真，第 20 条小命令出现在首次按键注入之前。

## 四、按键链路的当前判断

- 键表已确认：MENU = `0x1AC`，ADC 全局端口 `0x0F`（= 第二 ADC 单元 local ch3），电平 `0..0x5B`；
- 注入该电平后，模型侧记录 `[ADCRD] ch=3 val=0x0020`，说明**驱动确实读到了值**；
- 但尚无证据表明 `InputService::createEvent` 收到了 `0x1AC` 事件。

**下一步应直接观测 `InputService::createEvent`（libObj+0x3CFAEA）的 eventId 参数**，而不是继续扫端口。

## 五、下一步

1. 给 QEMU 钩子增加"记录 r1（eventId）"的输出，钩 `createEvent`，确认 MENU 是否到达 UI；

3. 若未到达，检查驱动侧按键上报条件（`get 0x1ac` 定向查询）；
4. 多时刻抓帧（vsync 3000/3600/4200）观察画面状态推进。
