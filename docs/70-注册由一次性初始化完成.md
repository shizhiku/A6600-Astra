# 70 · 注册由一次性初始化函数完成，中文需另一条路径

本轮为离线反汇编。无设备写入。

## 一、注册调用者是一次性初始化函数

反汇编 `0x54F3A2`（注册调用点 `0x54F42C` 所在函数）：

```
54f3a2  sub  sp, #0xc
54f3a4  ldr  r4, [pc, #0xa4]
54f3aa  add  r4, pc
54f3ac  mov  r0, r4
54f3ae  blx  0x104950        ; 初始化某对象
54f3b2  mov  r0, r4
54f3b4  blx  0xfe6a4         ; 加锁
54f3b8  ldr  r3, [pc, #0x94]
54f3ba  add  r3, pc
54f3bc  ldrb r5, [r3]        ; ← 一次性标志
54f3be  cbz  r5, 0x54f3ca    ; 已初始化则跳过
...
54f3ca  movs r2, #1
54f3cc  strb r2, [r3]        ; 置位标志
54f3ce  bl   0x54E518        ; 一串初始化助手
54f3d2  bl   0x54D08C
54f3d6  bl   0x54E1FC
54f3da  bl   0x54E434
54f3de  bl   0x54DF24
54f3e2  bl   0x54D408
54f3e6  bl   0x54D1AE
54f3ea  ...                  ; 取若干常量/字符串
54f404  bl   0x54F1FC
54f412  bl   0x5757E0
54f42c  bl   0x54E94C        ; ← 注册
```

**特征明确：带一次性标志位、连续调用多个初始化助手**，即文本渲染模块的一次性初始化（`TextRM_init` 一类）。

## 二、它只注册一次的原因

初始化期间只调用一次注册函数，说明**内置字体集合是一条固定条目**，而不是遍历 `fontlist.dat` 逐个注册。

因此：

- `FONT_UNIVERS` / `FONT_JAPANESE` / `FONT_KOREAN` 等内置字体由这条初始化路径处理；
- `FONT_S_CHINESE` / `FONT_T_CHINESE` 指向 `/tmp/images/`，属于**运行期动态获取**的字体，需要另一条路径（由副控制器传输完成后触发注册）。

## 三、与前面所有证据一致

| 证据 | 结论 |
|---|---|
| `/usr` 内只有 3 个 `.ltt`（无中文） | 中文不在固件内 |
| 相机 `/tmp/images/` 有中文 `.ltt`（1.96 MB，已采集） | 运行期由副控制器送來 |
| `libsencore.so` 含 `/tmp/images/...ltt` 路径 + 子系统通信代码 | 传输由该库负责 |
| 把字体文件放进 `/tmp/images/` 后 abort 位置不变 | 仅“文件存在”不足以触发注册 |
| 注册函数只被调用一次 | 内置路径，不覆盖中文 |

## 四、结论

**要让 UI 继续，必须让「副控制器 → /tmp/images → 注册」这条链路工作**，仅补文件不够。

这需要逆向 `libsencore` 的报文格式（其字符串提示：`Receive Pkt Err : resCode=0x%x, Adrs=0x%x, DataSize=0x%x`、`Offset > 300Byte` 分片等），在模拟器中实现对应的文件传输应答。

## 五、下一步

1. 逆向 `libsencore` 的请求/应答报文结构（分片大小 0x300、resCode/Adrs/DataSize 字段）；
2. 在 QEMU 侧对该通道实现“文件请求 → 返回 `/tmp` 中的字体内容”的应答；
3. 若成功，注册路径应被触发，`TextRM_loadFont` 可命中。
