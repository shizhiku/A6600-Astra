# 62 · 可复现的怪现象：复制镜像能启动、改过的镜像卡住

本轮为镜像制作与四次对照运行。无设备写入。

## 一、对照实验（配置完全相同，仅 `/usr` 镜像不同）

共同配置：`Backup-state1.bin` + 相机 libc 的 initrd + `norandmaps`。

| 镜像 | 内容 | 结果 |
|---|---|---|
| `nflasha15-copy` | **纯复制，字节不变** | **UI 启动**，在 libc `0x15796` 处 abort（`exception-monitor: 1`） |
| `nflasha15-listonly` | 仅替换 `fontlist.dat`（360→363 B，指向已有韩文字体） | **卡住**：无 `im.elf`，eMMC 调优刷屏，35 s |
| `nflasha15-font2` | `debugfs` 写入字体 + 改 fontlist | **卡住**（同上） |
| `nflasha15-font3` | **rw 挂载**写入字体 + 改 fontlist | **卡住**（同上） |

`nflasha15-copy` 重复运行两次，**均正常进入 UI**（结果稳定）。

## 二、排除的解释

1. **不是镜像损坏**：`font2`、`font3` 都通过 `e2fsck -fn` 且 `mount -o loop,ro` 成功；
2. **不是写入工具问题**：`debugfs` 与内核驱动 rw 挂载两种方式结果相同；
3. **不是 `/usr` 挂载失败那条日志**：能正常启动 UI 的 `nflasha15-copy` 运行里同样出现
   `mounting1 /dev/dnflasha15 -> /usr as ext2 failed. errno(6)`。

## 三、现象描述

失败运行的日志特征：

- 无 `im.elf` / `VPH` / `uxc` 任何输出；
- 大量 `AL_EMMC_SEQ (5729[execute_tuning]) : Warning : Software Tuning is forbiden for non-HS200 mode` 反复出现；
- 客户机时间仍推进到约 35 s，说明内核没死，只是某处停滞。

即：**改动过 `/usr` 镜像后，启动在更早阶段就停住，而不是走到 UI 才失败。**

## 四、当前无法解释之处

镜像内容不同不应影响内核行为（`/usr` 挂载在这些运行里都报了同样的失败信息）。因此怀疑：

1. 镜像文件在 Windows 盘上的**稀疏/分配差异**影响 `qemu-io` 写入结果；
2. 或启动停滞与镜像无关，而与被修改镜像的**文件时间戳/超级块状态**间接相关；
3. 或者存在尚未识别的外部因素（例如运行顺序、缓存）。

## 五、下一步（判别方法）

1. **对比日志分叉点**：把 `nflasha15-copy` 与 `nflasha15-font3` 两次运行的日志逐行比较，找出第一处不同的输出；
2. **再做一次「只挂载不修改」**：把镜像 rw 挂载后立即 umount（不改任何文件），若同样卡住，则说明问题来自超级块/时间戳更新，而非文件内容；
3. **改用拷贝方式做同尺寸替换**：把字体写成与某个已有文件等长的替换，避免新增目录项。

## 六、证据

- 镜像：`nflasha15-copy`、`nflasha15-listonly`、`nflasha15-font2`、`nflasha15-font3`
- 运行：
  - 成功：`cmdline-20261120T212203Z-51603`、`cmdline-20261120T213113Z-52339`
  - 卡住：`cmdline-20261120T212411Z-51766`、`cmdline-20261120T212643Z-51994`、`cmdline-20261120T212859Z-52177`
