# 04 · 风险与安全边界

## 1. 变砖风险（必须正视）

a6600 的 `/usr` 是 `nflasha15`，镜像 215 MB / 分区 300 MB。**改坏了，相机大概率起不来。**

关键机制：**USB 服务通道是 `im.elf` 建立起来的。** 如果 `/usr` 被改坏导致 `im.elf` 无法启动，
那么：

- 相机 UI 黑屏
- **USB 服务通道可能也一起消失**
- 官方升级程序（`FirmwareUpdaterEg.exe`）也要靠相机 OS 跑起来才工作
- 届时只能靠 **UART 串口** 救——而 **a6600 的 UART 测试点至今无人定位**

**结论：目前 a6600 没有验证过的救砖路径。这是 S5 之前最大的硬约束。**

## 4. 上机实验的前置条件（缺一不可）

在动任何写操作之前：

1. **全分区 dump**：`nflasha1 / 2 / 3 / 5 / 7 / 15 / B0`，逐个记 SHA-256
2. **验证恢复**：把 dump 原样写回一次，确认相机能正常开机
3. **第二台机器**，或**已定位的 UART 救砖点**
4. **byte-identical 先试**：内容一字节不改，只重打包，看相机是否接受

> 第 4 条是最有价值的实验：如果被拒，说明 256 B trailer 有校验，路封但相机无损；
> 如果被接受，说明封装完全正确，且**内容没变**，风险最低。
