# 24 · 真机基线地址映射与判据复核

本轮全部为离线分析 + 离线 QEMU 观测。无设备写入。

## 一、旧镜像地址 → 真机镜像地址

用指令片段在真机镜像中唯一定位：

| 项 | 旧镜像地址 | 真机镜像地址 | 偏移 |
|---|---|---|---|
| 致命写入点 | `0x63849F30` | `0x63858ADC` | `+0xEBAC` |
| 重试例程 | `0x638529D8` | `0x63861584` | `+0xEBAC` |
| 计数清零写入 | `0x63852A20` | `0x638615CC` | `+0xEBAC` |
| 初始化入口 | `0x635E1A6C` | 相同 | `0` |
| 进度报告函数 | `0x635E19D0` | 相同 | `0` |

该区域偏移恒为 `+0xEBAC`，与 QEMU 实测的故障 PC 差完全一致。

## 二、字面量解析（修正了一处公式错误）

真机镜像重试例程 `0x63861584` 的指令序列与旧镜像逐条相同。解析其 PC 相对字面量得到：

| 项 | 旧镜像 | 真机镜像 |
|---|---|---|
| 模块全局基址 r4 | `0x645C710C` | **`0x645DF53C`** |
| 对象指针槽 | `0x645CD160` | **`0x645E55D4`** |
| 状态指针槽 | `0x645CC0E8` | **`0x645E4558`** |
| 全局字节 | `0x644AE3A5` | **`0x644C4E43`** |
| 计数清零字节 | `0x644AE3A9` | **`0x644C4E47`** |
| 计数递增字节 | `0x644AE3AA` | **`0x644C4E4A`** |

**公式修正**：此前假设 `add rX, pc` 紧跟对应 `ldr`，按 `ldr+6` 计算 PC。当中间隔了其它指令时会差 6 字节。正确做法是逐条扫描 `add rX,pc`，用该指令地址 + 4 作为 PC。上一轮据此读错了两处地址（`0x645E55CE` vs 正确 `0x645E55D4`），现已改正。

## 三、真机基线下的判据数值（QEMU 实测）

在真机镜像下断于计数写入点 `0x638615DE`：

| 项 | 地址 | 实测值 |
|---|---|---|
| 状态指针槽 | `0x645E4558` | `0x6444E510` |
| 状态结构内容 | `0x6444E510` | `00 00 03 02 …` → `[+1]=0`、`[+2]=3` |
| 对象指针槽 | `0x645E55D4` | `0x640E46A0` |
| 对象前 4 字节 | `0x640E46A0` | `39 0D 00 04` → `[obj+3] = 0x04` |
| 全局字节 | `0x644C4E43` | `0x04` |

计算：

```
r5 = (0x04 ^ (0x04 << 4)) & 0x7F = 0x44  ≠ 0
[state+1] = 0 ≠ 1
```

两个清零条件都不成立 → 走累加分支，最终写状态 7、发消息 `0x3A`、触发空地址陷阱。

## 四、结论

**判据失配与镜像构建无关。** 真机构建与更新包构建在这四项状态上数值完全相同（`[obj+3]=0x04`、全局=`0x04`、`[state+1]=0`、`[state+2]=3`），行为一致。

因此问题仍然是：**在模拟环境里，没有任何东西把 `[obj+3]` 变成 `0x40`**，而真机上应当有。
