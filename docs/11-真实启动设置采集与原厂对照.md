# 11 · 真实启动设置采集与原厂对照

## 本轮范围

用户连接 a6600 后，仅通过 PMCA Senser 文件读取接口取得现有文件。没有执行终端命令、生成备份、写入相机配置、刷分区或操作物理 SD 卡。进入/退出服务认证导致 USB 模式切换；首轮切换超时后，确认服务设备已经重新连接，再进行第二轮读取。

设备专属备份应保持私有，不纳入公开仓库或可分享方案包。

## 原厂固件重放

- 使用原厂 /usr 分区，在独立 qcow2 覆盖层中放入捕获的四份设置文件。
- 同时将真实 Backup.bin 按其头部地址载入模拟 RAM。
- 基础 eMMC 分区表仍由更新包合成，未采集分区仍为空白或 fixture，不能称为完整真机镜像。
- QEMU 运行上限为主机时间 90 秒，结束码 124 来自 timeout。
- 本次未加载 ASTRA UI 或测试最小垫片。

日志：a6600_port/emulation/captured-stock-20261120T151942Z-27058。

## 实际观察

相比此前合成设置的原厂对照：

- 日志不再出现 backup_init error (selct_path)。
- 模块列表包含 backup、osal_ulogio、dmm 等之前失败的模块。
- FixedAreaTop 从 FFFFFFFF 变为 20098000，FixedAreaSize 为 0007C000。
- 不再出现 ERROR : Failed to mmap!。
- 随后出现内核异常：Unhandled fault: page domain fault (0x81b) at 0x00000000。
- 故障进程为 liro-kliro_66，PC 0x63849f30，LR 为 osal_snd_msg+0x150/0x174。
- 未观察到菜单输出，原厂基线仍未通过。

这组结果支持“真实设置组合消除了早期设置服务失败”，不能将改善单独归因于四个文件中的某一个。新内核异常的因果关系尚未确定，不能归咎于 ASTRA 补丁。
