## 二、最终成果

### 2.1 能做什么

a6600 的 QEMU 环境中可以启动 ZV-1M2 的五代 ASTRA 菜单，并用鼠标**点击和拖动**真实驱动它：

| 界面 | 状态 |

| 实时取景界面（`NO CARD`/`AF-S`/`ISO AUTO`） | ✅ |
| `My Menu` 主菜单（52 页） | ✅ |
| `Add Item` 全分类选单（41 项） | ✅ |
| `Main` 快捷设置面板 | ✅ |
| 菜单层级进出、翻页、唤面板 | ✅ |

### 2.2 三个关键结论

**① 原厂二进制零修改**

参考工程（ZV-E10）需要改 `im.elf`、`libMWF.so`、`libObj.so`、`libIMDB.so` 四处。
本移植**一处都不需要**——改走 `/etc/ld.so.preload` 注入后全部绕过。
四个文件与原厂逐字节一致（可审计复核）。

**② 五代 appFw.so 仅改 302 字节**

151 处等长同哈希符号改名，全在 `.dynstr`。代码段、数据段、重定位表未动。

**③ base 反推偏移是命门**

`0x8A2408`(ZV-E10) → `0x8436FC`(a6600)。
这一步错了，后面所有 `base + 偏移` 全错位——这正是早期所有崩溃的根因。

## 六、走过的弯路（供后来者参考）

| 弯路 | 教训 |
|---|---|
| 改 `im.elf` IMDB 开关 | 在 a6600 上完全无效，白费两轮 |
| 改名 `libObj` 的 `.dynstr` | 打断 `libIMDB` 的 dlsym，直接启动失败 |
| 覆盖三代 UI 索引 | 三代菜单崩溃；后经证实只要垫片先进就没问题 |
| 用本机 gcc 编垫片 | 需要 GLIBC 2.34，相机只有 2.11.2；必须用 zig |
| 用 QEMU gdbstub 传触摸坐标 | 走当前 CPU 上下文翻译，写不到目标页；必须由机型直写物理内存 |
| `pmemsave` 用绝对路径 | 监视器把 `/` 当除法，报 `invalid char 't'` |
| 预热点击用 `(636,476)` | 正好点在 `MENU Close` 上，把刚切的菜单关掉 |
