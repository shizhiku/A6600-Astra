# 28 · 按键直注通道（用于测按键映射）

> 时间：2026-11-24
> 目的：让用户能真实测试「哪个按键产生什么功能」

---

## 一、为什么原来的按键按钮无效

网页上原有的 MENU / ENTER / SEL 按钮走的是 `REA_CTL_FIFO` → 相机输入驱动。

实测：

```
[CTL] MENU press        ← QEMU 收到了
（垫片侧无 KEY_BRIDGE）  ← 没有传到 ASTRA
连按 3 次 ENTER，PCM_OPEN 计数不变（仍为 6）
```

**根因**：垫片在 handoff 时释放了四代输入队列，
`InfraInput::SetCallback` 不再被调用；而 CTL 注入只喂到该队列，
所以按键在 UI 层完全无效。

（触摸之所以能用，是因为走的是另一条路：信箱 → `postMouse*` → 控件系统。）

---

## 二、新通道：五代事件直注

绕过已失效的四代队列，直接把**五代按键事件**送进 ASTRA 的事件队列。

### 2.1 链路

```
网页按钮 → /key?on=<ev_on>&off=<ev_off>&hold=<ms>
   → live/touch.txt 追加 "k <on> <off> <hold>"
   → 宿主 'T'+28字节 写入 REA_CTL_FIFO（kind=3）
   → QEMU address_space_write 写入 guest 信箱
   → 垫片轮询到 kind==3
   → g5_send_internal_event(ev_on) → usleep(hold) → g5_send_internal_event(ev_off)
```

日志示例：

```
KEY_HOST: on=0x2010003 rc=0 off=0x2010004 rc=0 hold=100ms
```

### 2.2 事件 ID 与功能对照

直接取自垫片内置的 `g5_tact_key_table`（与五代固件一致的按键定义）。

**核心拍摄与拨轮**

| 按键 | 功能 | press | release |
|---|---|---|---|
| S1 | 半按快门：自动对焦 + 测光（快门第一行程） | `0x020e000e` | `0x020e000f` |
| S2 | 全按快门：完成拍摄（快门第二行程） | `0x020e0000` | `0x020e0001` |
| REC | 视频开始 / 停止录制 | `0x020f000d` | `0x020f000e` |
| WHEEL_L | 前拨轮左转（光圈/快门/ISO） | `0x02050001` | 无 |
| WHEEL_R | 前拨轮右转（光圈/快门/ISO） | `0x02050000` | 无 |
| MS_UP | 五维摇杆上（移对焦点 / 选菜单） | `0x02010011` | `0x02010012` |
| MS_DN | 五维摇杆下 | `0x02010014` | `0x02010015` |
| MS_LF | 五维摇杆左 | `0x02010017` | `0x02010018` |
| MS_RT | 五维摇杆右 | `0x0201001a` | `0x0201001b` |
| MS_ENT | 摇杆按下确认（近似 ENTER） | `0x0201001d` | `0x0201001e` |

**导航与功能**

| 按键 | 功能 | press | release |
|---|---|---|---|
| UP | 方向键上 | `0x02010000` | `0x02010001` |
| DOWN | 方向键下 | `0x02010003` | `0x02010004` |
| LEFT | 方向键左；**子页面时为返回上一级** | `0x02010006` | `0x02010007` |
| RIGHT | 方向键右 | `0x02010009` | `0x0201000a` |
| ENTER | 确认 | `0x0201000c` | `0x0201000d` |
| MENU | 打开系统设置菜单 | `0x0201000f` | `0x02010010` |
| FN | 自定义功能键：调出快速设置 | `0x02020000` | `0x02020001` |
| PLAY | 进入回看界面 | `0x02020003` | `0x02020004` |
| DELETE | 删除当前回看的文件 | `0x02030000` | `0x02030001` |
| C1 | 自定义按键 1（对焦切换 / 参数调整） | `0x02060000` | `0x02060001` |

**SEL 快捷档位**

SEL1-1…SEL1-5 / SEL2-1…SEL2-5 是**预设快捷档位**，
走 ADC 模拟量通道（非五代事件），触发后 **1.2 秒自动释放**，属短按模拟。
用于快速切换参数预设、调用自定义功能组。

## 三、首次扫描结果

界面：`My Menu`（1/52）→ `Main` 快捷设置面板（8/52）之间。

| 按键 | 是否可见变化 | 观察到的效果 |
|---|---|---|
| **UP** | ✅ | 从 `Main` 面板回到 `My Menu`，左侧图标栏焦点移到星形（My Menu） |
| **DOWN** | ✅ | 从 `My Menu` 进入 `Main` 快捷设置面板（8/52） |
| **RIGHT** | ✅ | 在面板内焦点右移（左栏 `Main` 变橙色选中，焦点进入右侧设置宫格） |
| LEFT | ✗ | 无变化（当时已在最左） |
| ENTER | ✗ | 无变化（当时焦点不在可执行项上） |
| MENU | ✗ | 无变化 |
| MS_* 四个 | ✗ | 无变化 |
| FN / PLAY / DELETE / C1 / REC / S1 / S2 / WHEEL_* | ✗ | 无变化 |

### 3.1 用户实测结果（2026-11-24）

| 按键 | 功能 | 备注 |
|---|---|---|
| **UP** | 向上移动 | ✅ 确认 |
| **DOWN** | 向下移动 | ✅ 确认 |
| **LEFT** | **返回上一级** | ✅ 确认（首次扫描时因已处于最左而未观察到） |
| RIGHT | 未单独确认 | 首次扫描中在 `Main` 面板内使焦点右移 |
| 其余 | 未测完 | 期间界面卡住，未能继续 |

> LEFT = 返回 这一点很重要：它说明方向键不只是移动焦点，
> LEFT 兼具"返回"语义。这与五代 UI 的交互设计一致。

### 3.2 一次卡死的记录

实测过程中界面卡住一次。日志显示根因是**应用层屏幕栈进入非法状态**：

```
PCM_OPEN #13: cur=0x1b3 next=0x2ec  → rep_shooting -> scr0132_0001
PCM_OPEN #14: cur=0x2ec next=0x0    ← 目标屏幕为 0（非法），随后无任何 open screen
```

同期的其它指标均正常：

- QEMU 进程存活
- 宾客机时间继续推进（+729 s）
- `G5_APPFW_DRAWFB` 仍在递增（#23400）
- `exception monitor` = 0

**⇒ 不是模拟器死机，是 ASTRA 的屏幕状态机走坏了。重启即可恢复。**

触发条件未知（可能是某次按键把当前屏引导到一个不存在的 next）。
后续若复现，应记录卡死前最后 10 条 `KEY_HOST` / `TOUCH_HOST` / `PCM_OPEN`。

### 3.3 关键判读

**20 个键全部 `rc=0`** —— 说明事件都成功进入了 ASTRA 事件队列。

`rc=0` 只代表"事件已投递"，**不代表当前界面有响应**。
比如已经位于最左侧时再按 LEFT，自然无变化；
焦点不在可执行项上时按 ENTER，也不会有效果。

**⇒ 要测出完整映射，需要在不同界面、不同焦点状态下反复试。这正是现在可以手动做的事。**

---

## 四、怎么用

打开 **http://127.0.0.1:8790/** ，右上新增面板「**按键测试（五代事件直注）**」：

- 20 个按钮，各自对应一个五代按键
- 「按住时长」可调（默认 80 ms，某些操作可能需要更长）
- 点击后看画面变化

> 上面原有的 MENU / ENTER / SEL 按钮走的是已失效的 CTL 通道，**测映射请用新面板**。

## 五、已知限制

| 项 | 说明 |
|---|---|
| 单次点击 | 每次发 press→hold→release，不支持长按组合 |
| 组合键 | 未实现（如 MENU+滑轮） |
| 效果依赖上下文 | 同一按键在不同界面效果不同，属正常 |
| 画面刷新 | 约 4 s 才能反映变化（宾客机重绘慢），点完稍等再看 |
