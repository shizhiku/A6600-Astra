## 二、容器结构（已验证）

```
0x00000000  UFU 魔数      89 55 46 55 0d 0a 1a 0a
0x00000008  DATV  len=4
0x00000014  PROV  len=4
0x00000020  UDID  len=92
0x00000084  FDAT  len=316,672,272     ← 固件本体（加密）
0x12E0099C  DEND  len=4
0x12E009A8  文件结束（剩余 0 字节）
```

块格式：`[u32 大端长度][4 字节标签][长度字节数据]`

**校验依据**：同结构对照 ZV-1M2 的官方 `BODYDATA.DAT`（627,176,840 B），
它同样以 `DEND` 结束且剩余 0 字节。我们这份截断后也剩余 0。

加密开销比例也吻合：

| 机型 | 解密后载荷 | BODYDATA 中 FDAT 块 | 差值 |
|---|---|---|---|
| a6600 | 315,434,496 B | 316,672,272 B | +1.24 MB（0.39%） |
| ZV-1M2 | 624,726,016 B | 627,176,720 B | +2.45 MB（0.39%） |

## 三、提取方法（可复现）

```python
d = open('Update_ILCE6600V110.exe', 'rb').read()
magic = b'\x89UFU\r\n\x1a\n'
off = d.find(magic)          # 本例 = 0xAE9D4
blob = d[off:]
# 顺序走块，遇到 DEND 后即为容器终点
end = 0x12E009A8             # 由块遍历得出
open('BODYDATA_ILCE6600.DAT', 'wb').write(blob[:end])
```

**要点**：
- 升级包是 `PackmanExtractor`（Sony Packaging Tool v5.0），载荷**附在 PE 镜像之后**
- 长度字段是**大端**
- `DEND` 之后还有约 8.68 MB 的 exe 残留数据，**必须截掉**

## 四、SD 卡恢复流程（索尼官方文档）

来源：索尼支持《相机在 SD 卡更新时卡住？》（[英文](https://www.sony.co.uk/electronics/support/a-mount-body-ilca-70-series/ilca-77m2m/articles/00300065)、[中文相关](https://www.sony.com/zh-cn/electronics/support/lenses-a-mount-lenses/sal1118/articles/00138868)）

```
1. 准备一张 SD 卡，在相机或电脑上格式化（FAT32）
2. 把 BODYDATA_ILCE6600.DAT 复制到卡根目录
3. 重命名为 BODYDATA.DAT（必须正好是这个文件名）
4. 相机装电池（满电）、插入该卡
5. 开机 → 进入菜单「设置 → 版本」→ 执行更新
```

**官方强调**：
- 文件名不能变成 `BODYDATA.DAT(1)` 之类
- 必须重新下载/复制，不要用旧的副本
- 更新中断可能造成永久损坏，务必满电

## 五、必须说清的不确定性

| 项 | 状态 |
|---|---|
| 容器结构与机型对应 | ✅ 已校验（与官方同结构样本对照） |
| 索尼文档化的 SD 卡更新流程 | ✅ 官方支持文档存在 |
| **a6600 是否支持 SD 卡更新** | ⬜ **未在真机验证**（a6600 说明书需确认） |
| **砖机能否自动进入更新** | ⬜ **未验证**——正常流程是从菜单发起 |
| 我们这份在真机上被接受 | ⬜ **未验证** |

**最重要的一条**：上面第 5 步"开机进菜单执行更新"要求**相机还能开机进菜单**。
如果相机已经砖到进不去菜单，这条路是否还能用，**没有证据**。

## 六、因此建议的验证动作（在任何修改之前）

```
① 把 BODYDATA.DAT 放上 SD 卡，插进相机
② 开机，进「设置 → 版本」
③ 看能否识别到固件（能看到版本号即可，不要确认更新）
```

- 能看到 → 这条路**至少对"能开机的相机"有效**，可作为一个恢复手段
- 看不到 → a6600 可能不支持 SD 卡更新，需要另找通道

**这一步本身是安全的**：只是让相机读取并显示，不确认就不会写入。
